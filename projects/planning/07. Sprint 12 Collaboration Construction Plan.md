## 5. Where the code goes

### 5.1 Three modules that exist and own nothing

`modules/attachment/`, `modules/comment/` and `modules/activity/` each hold a single `mod.rs`. Each takes the layout [coding standard](../../docs/standards/01.%20Coding%20Standard.md) §2.2 sets and `modules/workflow/` demonstrates: `domain/` for the vocabulary and the pure refusals, `repository/` for the statements, `service/` for the transactions and the permission checks, `handlers.rs` for the routes.

**`modules::activity` is called by four other modules and calls none of them.** Document, workflow, attachment and comment each write events; the activity module owns `activity_events` and offers one write function. That is the direction `modules::audit` already runs in, and the plan says so here because the alternative — each module writing its own `INSERT` — is four vocabularies for one table.

### 5.2 Two dependency families, decided here

Neither exists in `kelir-backend/Cargo.toml` today, and this project treats a dependency as a decision with a paragraph rather than a line in a manifest.

| Need | Decision | Why, and what was rejected |
|---|---|---|
| **Multipart upload** | `axum`'s own `multipart` feature | It is the framework already in the router, and it streams. The rejected alternative is reading the body into memory and parsing it, which makes #245 AC3 — *size is refused before the body is consumed* — impossible to satisfy honestly |
| **Object storage** | An S3-compatible client, pinned exactly | MinIO has been in the compose stack since Sprint 0 and is used by nothing; it speaks S3. **The choice between `aws-sdk-s3` and a smaller client is item 1's to make and to record**, against one criterion: the client must let the size limit be enforced on a stream rather than on a buffer |
| **ClamAV** | Item 3's, and **not** decided here | It depends on the measurement §2 says is outstanding. INSTREAM over TCP needs no crate at all; a crate is worth it only if the worker turns out to need more than one call. **Deciding it before the number exists is what D-4 did** |

**Configuration, not constants** (#245 AC5). The size limit, the accepted types and the object-storage endpoint are `KELIR_*` variables with defaults, and `.env.example` gains them in the same change — it is the file an operator reads, and eight variables that exist only in code are eight an operator cannot find.

## 6. The migrations, and the order the foreign keys impose

**The sprint plan lists the items 1–6 and this plan runs them 1, 6, 2, 4, 3, 5.** The reason is not preference:

```
activity_events.attachment_id  ->  attachments (id)     § 10.1
activity_events.comment_id     ->  comments (id)        § 10.1
comments.attachment_id         ->  attachments (id)     § 9.1
```

**`activity_events` cannot be created before `comments` exists**, and `comments` cannot be created before `attachments` does. The sprint plan's order puts the activity migration (item 4) two items ahead of the comment migration (item 6), which is a migration that will not apply. So the migration order is forced — **attachment, then comment, then activity** — and the item order follows it.

**Item 6 moves early as a whole item rather than having its migration split out.** A migration separated from the surface it serves is the `delegations` situation **D-13** spent two decisions undoing: a table with a writer and no reader, or in this case with neither.

**Item 5 stays last**, for the reason the sprint plan gives: it records what items 1, 2, 3 and 6 do, and an event writer that lands before its subjects is a writer with nothing to write.

## 7. Item 1 — attachments, the migration, the upload and the metadata ([#244](https://github.com/sujanto-gaws/kelir/issues/244))

`0031_attachment.sql` creates §8.1 `attachment_categories`, §8.2 `attachments` and §8.3 `attachment_versions`, and seeds the `attachment:*` permission rows. **`document_versions` and `retention_policies` already exist** — both in `0015_document.sql` — so the two foreign keys §8.2 declares can be real from the first day rather than deferred.

**`attachment_versions` is created and left unwritten**, and the migration header says which sprint fills it (FR-ATT-007, Sprint 13 stretch) — `0027`'s convention, and the thing #249 AC1 asks of the comment migration for the same reason.

### 7.1 The write that is two writes, and which failure is allowed

**#244 AC2 is the item's whole risk.** An object and a row, and no transaction spans both. The decision this plan takes:

**The object is written first, then the row, and the failure that is possible is an orphaned object.** A row with no object is a download that 500s for a person who has done nothing wrong; an object with no row is bytes nobody can reach, costing storage and nothing else. **The recoverable failure is the one that is allowed to happen**, which is AC2's own wording.

That leaves a sweep for orphaned objects as work this sprint does **not** do — named here so it is a decision and not an oversight. `storage_reference` is generated from the document and a fresh id (#244 AC6), never taken from the request, so an orphan is identifiable by the absence of its row.

### 7.2 What the upload refuses, and what it does not disclose

Uploading against a document the caller cannot read is refused **the way a read of that document is refused** (#244 AC5) — the same 404 the document surface gives, not a 403 that confirms the document exists. This is the [#171](https://github.com/sujanto-gaws/kelir/issues/171) visibility floor applied one table over: tenant scope plus the document-read permission.

`virus_scan_status` is `PENDING` and **nothing in this item sets it** (#244 AC3). The scan is item 3, and an attachment reading `CLEAN` because nothing scanned it is the failure the whole gate exists to prevent.

## 8. Item 6 — comments, moved early ([#249](https://github.com/sujanto-gaws/kelir/issues/249))

`0032_comment.sql` creates §9's three tables. `comment_mentions` and `comment_attachments` are created and left unwritten, with the migration header naming Sprint 13 (FR-CMT-005/006) — #249 AC1.

**`parent_comment_id` is created and nothing writes it**, and the header says so. Threading is FR-CMT-002 and Sprint 13; a column that exists is not a feature that exists, and the next reader will assume otherwise unless told.

### 8.1 The paragraph that has to be written before the first row

**This is not the decision comment**, and #249 AC3 makes the distinction a deliverable. FR-TASK-006 shipped in Sprint 11 as three columns written in one transaction — `workflow_tasks.comment`, `approval_decisions.comment`, `workflow_history.comment` — and that is a **record**: the reason an approver gave, immutable because the decision is. This is a **conversation**.

It is the fourth time this project draws such a line, and it should read like the three before it: `documents.status` against `workflow_instances.current_state` ([#178](https://github.com/sujanto-gaws/kelir/issues/178)), the three-way workflow record distinction ([#181](https://github.com/sujanto-gaws/kelir/issues/181)), and `activity_events` against `audit_events` in §10 below.

**Body normalization is `workflow::domain::task::normalize_comment`'s shape** (#249 AC4) — trimmed, bounded, and the refusal names the field. Whitespace becomes absent before anything else looks at it, which is the property record 09 §4 verified for #182 and the reason a required comment cannot be satisfied by the space bar.

## 9. Item 2 — download, and the boundary seen from both sides ([#245](https://github.com/sujanto-gaws/kelir/issues/245))

**Merged because they are one boundary**: what may be stored, and who may retrieve it.

**Download resolves through the document's read permission** (#245 AC1), not through the attachment's id — an attachment is only as private as the document it hangs on — and a caller who may not read the document gets the same answer whether or not the attachment exists (AC2).

**Size is refused before the body is consumed** (AC3). This is the criterion that drives §5.2's dependency choice: a limit enforced by measuring what has already been accepted is a limit on the disk, not on the upload. The refusal names the limit (AC6).

**Type is validated by content, not by extension** (AC4) — they disagree exactly when it matters. The accepted set is configuration (AC5), and the check runs on the sniffed bytes with the declared `mime_type` recorded rather than trusted.

## 10. Item 4 — activity, the migration and the lifecycle events ([#247](https://github.com/sujanto-gaws/kelir/issues/247))

`0033_activity.sql` creates §10.1 `activity_events` and seeds the permission its read requires. Both foreign keys it declares — to `attachments` and to `comments` — are real, because §6 put those migrations first.

### 10.1 The distinction, stated before the first row

**`activity_events` is a user-facing timeline** behind the document's own read permission, shown to whoever is looking at the document. **`audit_events` answers *was this tampered with*** — hash-chained, unchangeable, behind `master-data:audit:read`, read by somebody investigating. **Neither is derived from the other**, and record 09 §6.3 verified that claim for the workflow records by tracing every `INSERT` site and confirming `modules::audit` reads no workflow table. The same property has to be true here and has to be checkable the same way.

`modules::activity`'s own documentation carries it, naming all four records and saying which question each answers and who reads it (#247 AC3).

### 10.2 Append-only over the columns, not over the router

**#247 AC4, which is [#181](https://github.com/sujanto-gaws/kelir/issues/181) AC6's shape.** `activity_events` has no `updated_at` and no `deleted_at`, so an edit has nothing to stamp and a soft delete nowhere to write — and the test asserts that over `information_schema`, not over the absence of a route. A route that does not exist today is one somebody adds tomorrow.

**Every event is written in the same transaction as the thing it describes** (AC2). A timeline missing the event that mattered is worse than no timeline, and "best effort" is how that happens. This is deliberately **not** `audit::record_or_warn`'s pattern, and the difference is worth stating in the module documentation: an audit row that fails to write must not fail the business action, because the audit trail is a control over the action; an activity row that fails to write must fail it, because the timeline is part of what the action produced.

`actor_name` is denormalized at event time (AC5), so a timeline still reads correctly after a user is renamed or removed.

## 11. Item 3 — the scan gate ([#246](https://github.com/sujanto-gaws/kelir/issues/246))

**The only item in this sprint gated on something outstanding**, and §13 sequences it fifth so the measurement has the first two weeks to arrive.

**It does not start until a 25 MB scan has been measured by hand** (#246 AC6, and Sprint 12's own entry criterion). **D-4** chose ClamAV and sized nothing; the number decides whether the worker is a task on the same process or something the compose stack has to grow a service for, and that is a different item.

### 11.1 The gate is what the tests attack

**This is the only place in the product where a write is visible before it is safe.** So:

- `PENDING`, `INFECTED` and `FAILED` are **all refusals**, and `FAILED` is a refusal rather than a pass (#246 AC2). A scan that could not run has cleared nothing.
- The three are distinguishable to the caller (AC3), because *not yet* and *never* need different things from them.
- **The gate is enforced where the bytes are served** (AC4), not in the handler that lists attachments, and a test asserts it against the download path directly. A gate on the listing is a gate on the polite path.
- A scan result moves the row **exactly once** and cannot move it back out of `INFECTED` (AC5).
- **If ClamAV is unreachable, uploads succeed and downloads stay refused** (AC7). The failure mode is unavailability, never a silent pass.

Coding standard §2.9 applies in full: each of these is a security control, and each is accepted only after the defect is reintroduced and the test seen to fail.

## 12. Item 5 — the events for the epics, and the audit address ([#248](https://github.com/sujanto-gaws/kelir/issues/248))

Adding, downloading and removing an attachment writes an activity event; so does adding a comment (#248 AC1), each carrying the id of what it describes (AC2), each in the same transaction as the action (AC3).

**The audit address gap rides here because it is a parameter rather than a feature.** `audit_events.ip_address` exists, `middleware::client_address` resolves the caller's address and defends it against a spoofed `X-Forwarded-For`, the rate limiter consumes it — and **all 53 audit call sites pass `None`**, while that middleware's documentation says the audit row keys off it. An audit column that is always null reads as evidence the address was unavailable.

**One of two things happens, and either is acceptable** (#248 AC4/AC5): the address reaches the audit row, or the documentation stops claiming it does. **This is §3's cut candidate**, and if it is cut, the second option is what "cut" means — a comment describing behaviour the code does not have is the defect [#184](https://github.com/sujanto-gaws/kelir/issues/184) found in `TaskStatus::is_open` and record 09 found twice more.

The test asserts the address **on a written audit row**, not on the extractor (AC6) — the extractor already worked, and everything downstream of it was the gap.

## 15. Decisions this plan takes, and the one it owes

**Taken:**

1. **The items run 1, 6, 2, 4, 3, 5**, because `activity_events` and `comments` have foreign keys into tables the sprint plan's order creates later (§6).
2. **The migrations are `0031`, `0032` and `0033`**, and the three rows below them shift (§4).
3. **The object is written before the row, and an orphaned object is the failure that is allowed** (§7.1).
4. **An activity write failing fails its business action; an audit write failing does not** (§10.2). The two records answer different questions and the difference belongs in the module documentation.
5. **`axum`'s `multipart` feature and an exactly pinned S3 client**; the ClamAV client is item 3's and waits on the measurement (§5.2).
6. **The cut candidate is item 5's FR-AUD-005 half**, and cutting it means correcting the middleware's documentation rather than carrying the claim (§3, §12).

**Owed — and it is the same decision the retrospective's second action asks for:**

> **Who runs the closing independent pass, and on what date.** The date is proposed here as step 8's own step; the **party** cannot be set by this document, and naming one is what turns §2's rule from a hope into a criterion. Three sprints have now closed without a second reader and the fourth was rescued by a phase boundary. **If no party can be named at planning, sprint plan §2 should say what a self-pass is worth and `author-verified` becomes the expected label** — which is Sprint 10's fourth action, unmet in two sprints, and the alternative the retrospective states rather than a concession.
