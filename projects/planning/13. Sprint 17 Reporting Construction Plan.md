# Sprint 17 Reporting Construction Plan

**Status:** Adopted · **Last updated:** 2026-09-13

This decomposes [Sprint Plan](01.%20Sprint%20Plan.md) §5's Sprint 17 into the order it runs in. It sits **one level below** that plan, whose entry and exit criteria it does not change; where the two disagree the sprint plan wins.

It is the ninth construction plan, after [03](03.%20Sprint%208%20Form%20Renderer%20Construction%20Plan.md), [04](04.%20Sprint%209%20Document%20Construction%20Plan.md), [05](05.%20Sprint%2010%20Workflow%20Construction%20Plan.md), [07](07.%20Sprint%2012%20Collaboration%20Construction%20Plan.md), [08](08.%20Sprint%2013%20MVP%20Construction%20Plan.md), [10](10.%20Sprint%2014%20RAD%20Engine%20Construction%20Plan.md), [11](11.%20Sprint%2015%20RAD%20Authoring%20Construction%20Plan.md) and [12](12.%20Sprint%2016%20Phase%207%20Close%20Construction%20Plan.md), and **the first that opens a phase rather than continuing or closing one.** Related documents: the requirements are [SRS](../../docs/requirements/srs.md) §4.14, the reporting architecture is [architectures/06](../../docs/architectures/06.%20Building%20an%20ERP%20on%20Kelir.md) §7, the decisions this sprint is shaped by are **D-77**, **D-78** and **D-79**, and the findings it carries are [record 15](../verifications/15.%20Sprint%2016%20Independent%20Pass.md).

## 1. Three things this plan says before anything else

### 1.1 The sprint opens a module, and the page it is named after is the smallest part of it

**`kelir-backend/src/modules/reporting/mod.rs` is one line: `// reporting module scaffold.`** `DashboardPage.vue` is 81 lines and calls `/version` so that the API client has somewhere real to prove itself. **Nothing about reporting exists**, and a plan that sized the first row as *a card with a number in it* would be sizing the widget rather than the module under it.

**So §3 sizes item 3 against [#302](https://github.com/sujanto-gaws/kelir/pull/302) — the activity timeline, 867 lines — rather than against any widget in the tree.** What that pull request bought is the shape this one buys: a module directory, a repository, a handler, a permission in the catalogue, a route, an OpenAPI entry, a page and the tests that hold them. The widget is the last 80 lines of it.

**Items 4 and 5 are then cheap, and they are cheap for a stated reason rather than by hope.** Each inherits item 3's endpoint, its permission and its card, and neither invents a query shape — item 4 takes the inbox's own predicates and item 5 takes the document list's.

### 1.2 Two rows are about the project's own gates, and each is here on a position argument rather than on its size

**[#408](https://github.com/sujanto-gaws/kelir/issues/408) is first because a gate that can shut on a stranger's infrastructure has already shut once.** `End-to-end (browser)` has been a required check nobody can bypass since [#335](https://github.com/sujanto-gaws/kelir/issues/335) closed, and its browser install resolves a third-party apt index. **On 2026-09-09 that index advertised a file its mirror did not have, and for about forty minutes nobody in this project could merge anything** — including the merge that would have fixed it. This is [#274](https://github.com/sujanto-gaws/kelir/issues/274)'s argument one sprint later, with a reproduction instead of an absence of one.

**[#412](https://github.com/sujanto-gaws/kelir/issues/412) is second because `v0.8.0` is in the *other* sprint.** [Construction plan 12](12.%20Sprint%2016%20Phase%207%20Close%20Construction%20Plan.md) §7 step 3 established that **a control merged after the release it governs was never in force**, and put item 1 before the release run inside one sprint. **This plan takes the same rule one step further out**: the gate that `v0.8.0` must pass is fixed in the sprint *before* the sprint that tags, so the fix is not competing with a release run for the same days. The three defects are one issue because they are one file and one review — a `Final` record may cite a verification file that does not exist; rule 2 is satisfied by any of **eight** never-cited records, so `v0.7.0` could have closed citing a Sprint 12 read of work that shipped in `v0.6.0`; and **a record copied from the template exactly as the template's first line instructs carries two header status lines and reads `Template` for ever**.

### 1.3 Sprint 16 is not closed, and this plan is written anyway

> **Closed 2026-09-13** — after every row in §4 had merged. **The section is kept as written**, because what it predicted is what happened and editing it into the past tense would hide that.

**[Status report 17](../status/17.%20Sprint%2016%20Status.md) is `Draft` and retrospective 14 does not exist.** §2 of the sprint plan requires the retrospective in the same change as the report going `Final`, so the sprint is open by its own rule even though `v0.7.0` is tagged and [record 07](../releases/07.%20Release%20v0.7.0.md) is `Final`.

**That has two consequences and this plan states both rather than working around either.** The first is §2's entry table, where the criterion is listed **unmet** — it gates the sprint's start, not this plan's writing. The second is §6: **retrospective 14's actions cannot be placed because they do not exist yet**, and every construction plan since [07](07.%20Sprint%2012%20Collaboration%20Construction%20Plan.md) has had a section that places them. **This is the first plan in the project that has had to say it cannot**, and the commitment it makes instead is in §6 — the plan is amended when the retrospective lands, before construction reaches the row an action touches, rather than the actions being noted afterwards as things that did not fit.
