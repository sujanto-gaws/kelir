## 1. Where this demonstration stops

**Sprint 12 delivered no user interface, by its own plan.** `kelir-frontend/src/features/` has no `attachments`, `comments` or `activity` directory; the construction plan §1 defers the timeline UI to Sprint 13 and never scoped attachment or comment screens at all, on the stated reasoning that *a timeline with three sources and no screen is still worth having, and a screen over one source is not*.

**So the browser harness cannot reach any of it**, and substituting an API assertion is a thing that harness explicitly refuses. `e2e/support/api.ts`:

> The API, used for arranging — never for asserting. … What is deliberately *not* here is any helper that reads a list and returns rows. The assertion belongs in the browser — checking the API answered correctly would pass on a screen that renders nothing.

That rule is right and this record does not bend it. What it means is that **the exit sentence describes a user's day for a sprint that deliberately built no day to have** — which is the [Sprint 8 retrospective](../retrospectives/06.%20Sprint%208%20Retrospective.md)'s second action recurring two sprints after it was written: *an exit should name the artefact that must exist rather than describe a user's day*.

**What ran is the stronger half of what the criterion was for.** Every step below went through the deployed stack — release images, real PostgreSQL, real MinIO, real ClamAV — and the one thing no test in the suite can reach is the deployment working as a whole. It found three defects that had passed every test.

## 3. What the demo found

### Finding 1 — the deployed stack could not run the feature at all

`deploy/staging/docker-compose.staging.yml` gave the backend **`KELIR_STORAGE_DRIVER: s3` and nothing else**: no endpoint, no bucket, no credentials, no scanner. In that deployment:

* every upload would have addressed `localhost:9000` **inside the backend container**, where nothing listens;
* no bucket existed to receive one;
* and with no `clamav` service, every attachment that did land would have stayed `PENDING` for ever — the safe direction, and not a working product.

The `clamav` service went into the *development* compose with [#246](https://github.com/sujanto-gaws/kelir/issues/246) and not into this one. **This is the stack CI deploys and the [Sprint Plan](../planning/01.%20Sprint%20Plan.md) §2 environment clause names**, so "demoable from the Docker Compose stack built from release images" was false for three of this sprint's six items.

Fixed here: the storage variables, a `minio-init` that provisions the bucket, and the `clamav` service, with the `StreamMaxLength` warning from [#246](https://github.com/sujanto-gaws/kelir/issues/246) beside it.

### Finding 2 — `NoSuchBucket` on every upload, from a YAML folded scalar

With the stack fixed, the first run still answered **500**, and the backend log named it exactly:

```
NoSuchBucket: The specified bucket does not exist  (bucket=kelir)
```

`minio-init` had run and reported success. Its log said why:

```
Added `kelir` successfully.
sh: line 2: demo-only-minio-user: command not found
sh: line 3: demo-only-minio-password-9Hd3Bs: command not found
```

**A folded scalar (`>-`) folds lines into spaces — except more-indented ones, which it keeps literal.** The `command` had been split across lines for readability, so the container received three shell commands rather than one: `mc alias set` with no credentials, then the username and the password each executed as a command. It exited 0.

**The same defect was in `deploy/docker/docker-compose.yml`**, written the same way in the same sprint, and unexercised only because that bucket had been created by hand for the test runs. Both are now one physical line, with the reason written above them.

### Finding 3 — in this demo's own script

`Content-Disposition` came back absent because the check did a case-sensitive dictionary lookup, and HTTP does not promise header case. The header was correct throughout. Recorded because a demo that reports a false failure is a demo that will be disbelieved when it reports a true one.

## 4. What this does not cover

* **No browser.** §1. Nothing here says a screen renders anything, because there are no screens.
* **No second reader.** This was run by the party that wrote all six items, so it is evidence about the deployment and not about the code — [Sprint Plan](../planning/01.%20Sprint%20Plan.md) §2's rule is untouched by it, and the independent pass is still outstanding.
* **One tenant, one document, one file, one comment.** The path, not its edges; the edges are the integration suite's, and it has them.
* **The scanner cleared a file that was clean.** The infected path is proven in `attachment_scan.rs` against real ClamAV and by the [#246 measurement](https://github.com/sujanto-gaws/kelir/issues/246), not here.
* **The environment needed two shims**, both artefacts of this machine rather than the project: Docker Desktop's WSL integration is off here, so `docker` had to be given path translation and `WSLENV` forwarding. `deploy-local.sh` is unmodified and correct; anywhere Docker is native it needs neither.

## 5. Effect on the Sprint 12 close

**Exit criterion 1: met in substance, and the sentence needs rewriting rather than the work.** The path is demonstrated end to end against release images. It is not browser-driven and cannot be until Sprint 13 builds the screens — so the criterion as phrased will not be satisfiable by anything this sprint could have done, and the retrospective should say so rather than the status report claiming a pass.

**Three defects closed, all in deployment wiring, none reachable by any test.** Two of them would have made attachments non-functional in every real deployment while the entire suite stayed green. That is the argument for this criterion existing, and it is stronger after this run than before it.

**Criterion 2, the independent pass, is untouched** and remains the sprint's largest outstanding item — now for the third consecutive sprint, and with the construction plan §15's owed decision (a named party and a date) still unanswered.
