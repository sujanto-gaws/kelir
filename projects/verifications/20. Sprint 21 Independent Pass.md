## 3. Findings

### Finding 1: every tenant can resolve every `KELIR_INTEGRATION_SECRET_` variable. **Blocking. [#618](https://github.com/sujanto-gaws/kelir/issues/618).** Answers lead 1, turning on the tenant.

`domain::secret::environment_name_is_resolvable` checks the prefix and nothing else, and `outbound::resolve_secret` reads the process's environment. **P1**:
- A tenant was created through `POST /organization/tenants`.
- Its administrator sent `PUT /identity/roles/{their ROLE-ADMIN}` adding `integration:credential:create`, and got **200**. `organization::service` already says withholding it *"is not a boundary"*.
- They registered a system at their own address, with a credential naming the system tenant's planted variable, and made a test call. **Their collector received `Bearer r20-system-tenant-erp-token-5c5c`.**

`SECRET_NOT_FOUND` names the variable, so a set name answers differently from an unset one.

**The texts.** Installation §7.1 says *"put nothing under it but secrets meant for an external system"*, and never says *by any tenant*. `0049` says a new tenant's administrator *"cannot attach a credential … until somebody grants `integration:credential:create` deliberately"*, and that somebody can be the administrator themselves. D-96 (4) and ADR-0043 §O and §Q weigh only the deployment's own settings.

The existing `a_caller_in_another_tenant_calls_their_own_endpoint_and_neither_reaches_the_other` has tenant B resolve the system tenant's variable and asserts that it succeeds. **It holds the finding as isolation.**

### Finding 2: a decision during a reassign deadlocks, and the approver gets a 500. **Blocking. [#619](https://github.com/sujanto-gaws/kelir/issues/619).** Answers lead 2, through a lock the lead did not name.

- **The decision** takes the instance, then the task: `decide` calls `lock_instance` `FOR UPDATE`, then `lock_task`.
- **The reassign** takes the task `FOR UPDATE`, then inserts a `workflow_task_history` row. The row's `workflow_instance_id REFERENCES workflow_instances (id)` (`0025_workflow.sql:323`), so the insert takes `FOR KEY SHARE` on the instance.

**P2**:
1. The task was claimed.
2. The target role was held, so the reassign parked after `lock_task`.
3. The claimant's decision was seen waiting on `workflow_tasks`.
4. The role was released.

**The reassign answered 200. The decision answered `500 INTERNAL_ERROR`**, and the log said `deadlock detected`.

ADR-0042 §2 says *"A decision takes the task before `engine::fire` resolves an edge's role, so the order is the same"*. `reassign`'s doc comment says it keeps *instance first, then task* by taking only the second. **Record 18 §4 and record 19 listed explicit locks only, and so did this reading's brief.** `claim_task` and `delegate` insert the same history row after the same task lock. Neither was forced against a decision here (§5).

## 4. What was read and cleared

- **#592's egress pinning.** The host is resolved once and every address is checked. A per-call `PinnedResolver` answers only that host, and only with those addresses. IP literals skip DNS, and there is no proxy (`no_proxy()`, and `system-proxy` is off). The pool holds no idle connection, and TLS verifies against the host name. Decimal, short and hex IPv4 spellings are normalised before the check. **A mixed public and private answer is refused.** Redirects: `Policy::none()`, so a 3xx is `FAILED` and `Location` is never requested or stored.
- **`KELIR_INTEGRATION_ALLOWED_CIDRS`.** A malformed entry stops startup. It widens only the private class, so even `0.0.0.0/0` cannot open loopback or link-local. The test seams are never read from the environment.
- **Secret names.** Upper case, digits and `_` only, and the prefix is case-sensitive. A prefix with nothing after it is refused. The check comes before the read, so `DATABASE_URL` and `KELIR_JWT_SECRET` are refused. `Secret` has no `Debug`, `Serialize` or `Clone`, and is zeroised on drop.
- **#595.**
  - There is one writer, and it redacts before the insert. Reads return rows as stored, and the list carries no payload.
  - Filters refuse bad UUIDs, enums, repeats and zone-less dates as 422s. Every value is bound. Dates outside PostgreSQL's range, and inverted bounds, are 422s.
  - The detail route is scoped by tenant, so another tenant's id is a 404. The log pages use no `v-html`.
- **#562.** Provisioning withholds `integration:credential:*` by prefix, so a later code in the family is withheld too. New tenants get `integration:endpoint:call` and `integration:log:read`, and the `CHANGELOG` and the headers of `0049` and `0050` say so. Record 19's struck phrases survive only struck. #551, #552 and #553 are closed.
- **#586.** `lock_task` is `FOR UPDATE`, and `is_open` is checked right after it, with the write's own predicate as a second guard. Every closed status is a 409. A claim or a second reassign serializes on the task. `delete_role` locks the role and no task, so it forms no cycle with the reassign's task-then-role order. A target in another tenant is `ASSIGNMENT_UNRESOLVED`, and a task in another is a 404. **A reassign to a deactivated user is refused**, because deactivation sets `deleted_at` (`identity/repository.rs:575`), which `direct` checks. A user who is only `LOCKED` passes, and nothing claims otherwise.
- **#574, #585, #589, #584, #567, #580.** `definitions_naming_role` covers a state's assignment and every `allowedBy`, in `ACTIVE` revisions and in `DEPRECATED` ones with a running instance. The open-task list is tenant-scoped, and a foreign role is a 404. #584's clause is the same in its three copies, and it covers all five surfaces. Every `unresolvable` site takes a `Question`.
- **#578 and #588.** Only a throw is detected. The registry scopes this to SpiderMonkey's recursion, which is honest. **#588's either-or assertion is not vacuous**: it fails when nothing throws.
- **#597.** Six endpoints take `search`. `like_contains` escapes `\`, `%` and `_`, and a NUL is a 422. Stale answers are dropped by a ticket. Seven of the eight choosers either pick only a new value or know their current one.
- **The gates.** #560 and #561 hold within their stated limits. #569's normalisation resolves `./`, `../` chains and single percent-encoding correctly. #570 reads the tree at the tag and peels annotated tags. #582's stated limits cover what it misses. **#596's range handling is stricter than it needs to be** where a tag is missing, and CI fetches the full history. **This reader's ID is in no commit on any ref.**
- **The texts.** Every figure in status report 22 that one of the five readers recomputed from `git show --numstat` and `gh pr view` matches: the per-PR lines, the 33,818 and its split, the merge times and pairs, and the six new spec files. The *about 325* mutations are 331 by the table's own cells, which is within *about*. #591's image is the same index digest as `clamav/clamav:1.5.4`, and every deploy file and the docs name it.
- **Not re-filed.** The `\b` and `\B` reasons offer `[A-Za-z0-9_]` spellings without `REMEDY_LIMIT`. Record 19 §4 cleared their sentences, and they claim no agreement. **Record 18 §4's *"no path changes `candidate_role_id`"*** has been false since #586. It is a record, and this one notes it.
