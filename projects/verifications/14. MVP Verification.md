## 2. Method

- **The browser suite, in full: 14 specs, 14 passed, 46.8 s.** Driven by Playwright against the release stack, which is where eleven of the fifteen criteria are demonstrated.

## 4. Criterion 4, and the basis it is accepted on

**"Administrators can configure document types" is served by an API and by nothing else.**

`kelir-frontend/src/api/document-types.ts` exports one function — `listDocumentTypes`, a read, used by `NewDocumentPage` to fill a picker. `router/index.ts` has `admin/users`, `admin/roles`, `admin/delegations` and `admin/tenants`, and nothing for document types. Nothing in the frontend creates a type, binds a form or a workflow to one, or sets a numbering rule.

**This is the [construction plan](../planning/08.%20Sprint%2013%20MVP%20Construction%20Plan.md) §1.2 shape a third time.** That section established that *a criterion that says **users can** is not met by an endpoint*, and the project spent three `Should` rows buying screens for criteria 6 and 11 on that reasoning. Criterion 4 is phrased the same way, and it is the only *administrators can…* row without a screen — 2 and 3 both have one.

**One thing distinguishes it from 6 and 11, and it is the thing the decision rests on.** Those two had **nothing scheduled**: §1.2 found that no sprint in the plan would build them, which is what made the trade necessary. This has a scheduled owner — the backlog's RAD epic carries *Document type builder and menu builder UI · FR-RAD-004, 008 · `Should` · Sprints 14–16*. FR-RAD-008 is therefore split across an API (`Must`, Sprint 8, [#165](https://github.com/sujanto-gaws/kelir/issues/165)) and a builder (`Should`, after the tag).

**And there is a precedent inside this project for accepting it.** Sprint 8's exit sentence opens *"an administrator configures a document type against a published form"* and was recorded as met — with that clause performed over the API, which `a-document-is-created-and-submitted.spec.ts` says in its own comment: *"Configuring a document type has no screen until FR-DTYPE's, and this flow is about the document."*

> **Decided 2026-09-03 by the product owner: accepted, and recorded on this basis rather than ticked.** An administrator is a technical role, the API is a configuration surface, the builder is scheduled, and Sprint 8's exit already set the precedent.
>
> **What acceptance obliges** (**D-64**): [Product Backlog](../planning/02.%20Product%20Backlog.md) §5's criterion-4 row stops reading a silent *Covered* and says what the coverage is; and `v0.6.0`'s release notes say that document types are configured through the API, with the builder scheduled for Phase 7. **An MVP whose acceptance criteria are half-true in a table nobody re-reads is the failure this close plan exists to prevent** — the decision is defensible, the silence was not.

## 5. The probes

**Criterion 1, logout** — deleted after it answered, and rebuildable from this:

```ts
await page.goto('/login')                      // sign in
await page.getByLabel('Sign out').click()      // the control in AppLayout
await expect(page).toHaveURL(/\/login$/)
await page.goto('/documents')                  // and the session is gone
await expect(page).toHaveURL(/\/login/)
```

Passed in 2.9 s. The second half is what makes it a logout rather than a redirect.
