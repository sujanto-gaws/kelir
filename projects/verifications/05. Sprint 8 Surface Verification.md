## 1. Why this pass happened, and where its independence stops

[Sprint plan](../planning/01.%20Sprint%20Plan.md) §2 makes an item whose author is also its only verifier `In progress` rather than Done. Every Sprint 8 construction pull request was authored and verified by a single agent, and Sprint 9's first entry criterion names this pass.

**The verifier authored none of the eight construction pull requests above and did author the four finding fixes closed in the same sprint** — [#202](https://github.com/sujanto-gaws/kelir/issues/202), [#203](https://github.com/sujanto-gaws/kelir/issues/203), [#204](https://github.com/sujanto-gaws/kelir/issues/204) and [#206](https://github.com/sujanto-gaws/kelir/issues/206). Saying so is the point: an audit hash format, a mail path, a tenant-scope assertion and four repository predicates each carry a named mutation seen red, which is what [coding standard](../../docs/standards/01.%20Coding%20Standard.md) §2.9 requires and is not the same as a second reader. The [Sprint 8 retrospective](../retrospectives/06.%20Sprint%208%20Retrospective.md)'s third action makes that a rule rather than this record's disclaimer.

**The prior on entering.** Records 01–04 each covered a surface whose author had reported it sound, and each found six or seven defects. Two things argued for a *lower* prior this time and one argued for a higher one. Lower: Sprint 8 is the first sprint whose construction had a written plan before its first commit, and the first whose frontend work had a browser harness pointed at it as it landed — its own construction closed five findings in the branches that found them. **A mutation campaign of 27 over the SQL predicates Sprint 8 added**, every one compiled, executed against the test binaries able to see it, and reverted before the next. The boundary, stated because an absence of findings means something only with an edge round it: the campaign covers **every `WHERE` predicate and lock clause in the statements this sprint wrote or rewrote** — `find_active_rule`, `furthest_key`, `bucket_sequence`, `highest_issued`, `find_rule`'s lateral join, `replace_rule`'s deactivation, `deactivate`, `lock_type_binding` (including its lock *strength*), `count_documents_without_a_pinned_form` and `find_submission`. Record 03 recorded that shape; records 04 and 05 have not had to rediscover it.

### F1 — the ratio fell again, on the first run of the rule written to watch it

The campaign is not a judgement about effort. Sprint 8 wrote **more** tests than Sprint 7 and its own construction closed five findings; what the ratio measures is whether the *predicates* the sprint added are held by any of them, and three sprints of that measurement now read 65%, 37%, 22%.

**Why this sprint's number is low is legible, which is what makes it worth acting on rather than lamenting.** Sixteen of the twenty-one survivors are second layers behind first layers that work — the shape record 04 named and [coding standard](../../docs/standards/01.%20Coding%20Standard.md) §2.5 now carries a rule for. The other five are F2. What no rule yet covered is the *fixture* half: a predicate goes unexercised most often because the database the test runs against holds exactly one of the thing the predicate scopes by.

### F2 — five guards nothing holds, and one reason for all five

| Predicate | What defeating it does |
|---|---|
| `find_active_rule` · `document_type_id = $2` | `allocate_in` finds *some* active rule of the caller's tenant, so a document of type A can be numbered from type B's template and B's sequence |
| `find_rule` · `rule.is_active` | A type whose numbering was cleared reads back through `GET /numbering-rule` as though it still had one |
| `furthest_key` · `document_type_id = $2` | The closed-bucket refusal is decided from another type's buckets, so a legitimate allocation is refused and a back-dated one admitted |
| `bucket_sequence` · `sequence_key = $3` | The rule endpoint reports a next number from whichever bucket the planner returns first |
| `count_documents_without_a_pinned_form` · `document_type_id = $2` | Any unpinned document of any type blocks a rebinding of any other type — **D-30**'s guarantee widened into a refusal nobody can clear |

**One cause, and it is the fixture rather than the assertion.** Every test above builds a database containing exactly one document type, so *scoped by type* and *not scoped at all* are the same observation. It is the three-move rule ([#200](https://github.com/sujanto-gaws/kelir/issues/200)) one level up: two moves cannot distinguish "separate" from "overwritten", and one subject cannot distinguish "scoped" from "unscoped". Coding standard §2.9 gains that sentence in this branch; the five tests belong to whoever takes [#218](https://github.com/sujanto-gaws/kelir/issues/218).

### F3 — a refusal an administrator reads, with fourteen spaces in the middle of it

`guard_rebinding`'s message and `router.rs`'s OpenAPI assertion each held a run of fourteen spaces where a backslash-continued line had been folded into one. The first is user-facing: the administrator told why a rebinding was refused reads *"…pinned no form revision, so&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;they render against…"*. `/forms/:id` renders a published definition; `/api/v1/document-types/{id}` configures which form a type binds. Nothing reads the second to reach the first, so *"a user opens that type"* is not a thing a user can do. Both halves are built and each is demonstrable on its own. Recorded rather than filed because [#167](https://github.com/sujanto-gaws/kelir/issues/167) — create a document *from a type* — is exactly that traversal and is Sprint 9's item 1.

## 4. What was checked and found sound

**The Tamper-Proof Pattern is implemented where it claims to be, and its order is the specification's.** `secure_payload` discards keys the definition does not declare, rebuilds datagrid rows from the row template, re-evaluates every `calculate` by *declared* mode, then strips by `conditional` — calculation before stripping, which is JFSS §9.2's order and **D-27**'s reversal of the construction plan. The reversal is the safer one by a margin that is not close: strip first and a `conditional` keyed on a computed field is decided from the client's number.

**The fixed point is bounded, and a cyclic definition is a refusal rather than a hang.** `calculate_to_fixed_point` runs at most `count_calculated + 1` passes and answers `CALCULATION_DID_NOT_SETTLE` beyond it. A chain of *n* calculated fields declared in the worst order settles in *n* passes and the *n+1*-th confirms it, so the bound is tight rather than arbitrary — and a definition with a cycle, which nothing rejects at save yet, cannot spin the server.

**A submission's cost is bounded before the expensive work starts.** `bounded()` refuses a payload over 1 MiB *before* the re-evaluation, and the doc comment gives the reason a reader would otherwise have to reconstruct: the walk clones the scope once per calculated field, so an unbounded payload is unbounded work as well as an unbounded row.

**A registry rule this side is the right side for and has not built refuses the submission rather than passing it.** `unique`, `exists` and `authorized` each carry `decide: None` with an `unenforceable` reason naming the sprint that will build them (**D-28**). That is the same position the construction plan took from the other end by keeping a `unique` out of the shared fixture — a rule silently unrun is the defect class this whole item exists to remove.

**The rebinding guard locks what its check read.** `lock_type_binding` takes `FOR UPDATE` on the `document_types` row; inserting into `documents` takes a `FOR KEY SHARE` on that same row, and PostgreSQL's lock matrix makes the two conflict while `FOR NO KEY UPDATE` would not. The strength is load-bearing, it is documented as such, and the campaign confirms a test notices when it is weakened.

**Every Sprint 8 route reaches the OpenAPI document and requires its own permission.** `every_annotated_route_reaches_the_document` walks both directions and the per-route permission tests cover the RAD and document-type surfaces, including the three numbering routes whose authorization was asserted by nobody until #165's follow-up commit added them.

## 5. What was not reached

**No Playwright flow was run by this pass.** The five specs were read and their assertions traced to the code they drive, but running them needs the release images and a deployment, which this pass did not bring up. **They are not unrun**: CI's `End-to-end (browser)` job brings up the release images and runs all five on every pull request, so the evidence exists and belongs to the pipeline rather than to this record. What this pass cannot say is anything about a flow's *reach* — whether an assertion that passes is asserting what its name says — which is the question a browser harness needs asked of it exactly once, by somebody who did not write it.

**The frontend campaign is four mutations, not a sweep.** `useFormEvaluation.ts` and `validation.ts` are roughly 1,300 lines between them; four mutations establish that the mode branch, the generated guard, the division-by-zero configuration and the required check are each held by a test, and say nothing about the rest.

**The re-evaluation's Rust-level predicates were read and not mutated.** The campaign is a SQL campaign by design — that is where three sprints of coverage findings have been — but `secure_payload`'s branches are exactly the kind of second layer §2.5's new rule is about, and a mutation set over them is the obvious next campaign.

**The four finding fixes closed in this sprint were not read**, for the reason §1 gives.
