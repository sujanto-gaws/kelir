## 3. Findings

### Finding 1: #459 was read only by the session that wrote it, and `git log` cannot tell. **Blocking for `v0.8.0`, as a claim, not as code. [#464](https://github.com/sujanto-gaws/kelir/issues/464).**

§1 gives the evidence. **It is [record 15](15.%20Sprint%2016%20Independent%20Pass.md) finding 4 in a form that is harder to see.** There, the reader found its own ID in four trailers and said so. Here there is no trailer to find, so the same check comes back clean. It is clean because the author left nothing to match, not because the author is someone else. **#459's own new bullet names this gap**: *"a record that fails the criterion and does not say so passes both tests"*. That bullet is itself the commit that fails the criterion.

**Two facts for [D-84](../planning/02.%20Product%20Backlog.md), which asks whether a trailer-less commit is refused or named:**

1. **A local session can read its own ID.** D-84 says #459's session "could not". This reader, a subagent of that session, read it from `CLAUDE_CODE_SESSION_ID`. It is a UUID, so a rule requiring `https://claude.ai/code/session_…` would refuse every local session that complies.
2. **A subagent inherits its dispatcher's session ID.** Any reader that a session dispatches as a subagent is, under §2's criterion, that session. It can therefore never be independent of that session's commits, however little reasoning it inherits. Record 15's reader was also dispatched by its author. This is the mechanism behind both cases.

**Why blocking.** §2 attaches the requirement to the tag, and record 15 set the precedent: a tag taken on a record that fails the criterion satisfies the rule in form only. **The same two discharges are open:** a reader outside `1d834a2a-…` reads #459 (finding 6 lists what it should settle), or [record 08](../releases/) states that #459 was read only by its author and the release was taken anyway. **#459 is 9 lines of project text with no predicate**, which is an argument for the second discharge. It is not a reason to skip the decision.

### Finding 2: the pattern refusal still stores about twenty constructs the two engines read apart, and four texts say the divergence is closed. **Not blocking. [#465](https://github.com/sujanto-gaws/kelir/issues/465), `sprint:19`.**

**`^.{1,3}$` rejects two emoji in the browser and accepts them on the server, and the definition is stored with a `201`.**

#451 closed the three constructs [record 15](15.%20Sprint%2016%20Independent%20Pass.md) finding 1 found. P1 found these, all of them divergent on the two engines and all stored:

| Construct | Example, subject | ECMA-262 | `regex` crate |
|---|---|---|---|
| `.` against `\r`, U+2028, or a character outside the BMP | `^.{1,3}$`, two emoji | false | **true** |
| A literal astral character in a class | `^[😀]$`, 😀 | false | **true** |
| Nested classes and set operations | `^[[a-c]]$`, `b`; `^[a-z&&[^aeiou]]$`, `b` | false | **true** |
| | `^[a-z--b]$`, `b` | **true** | false |
| Braced and 8-digit hex escapes | `^\x{41}$`, `^\u{41}$`, `^\U00000041$`, `A` | false | **true** |
| Crate-only anchors | `\Aabc`, `abc\z`, `\<cat`, `cat\>` | false | **true** |
| `\a` | `^\a$`, `a` | **true** | false |
| Case folding under `i` | `^k$`, U+212A; `^s$`, U+017F | false | **true** |
| `$` under `m` before `\r\n` | `^a$`, `a\r\nb` | **true** | false |
| Crate-only group syntax | `(?i)abc`, `(?P<x>a)`, `(?x) a b` | **SyntaxError** | compiles |

**The last row is #391's defect reversed.** `validation.ts` treats a pattern it cannot build as a violation, so every value fails in the browser, while the server accepts the definition.

**The cause is the one record 15 named, still unanswered.** Its §6 asked *"whether ADR-0038's dialect is the set the crate compiles or the set both runtimes agree on, which is a decision and not a scan."* #451 answered with a longer scan. ADR-0038's amendment calls it *"the decision applied rather than changed"*. **That is accurate, and it is why the gap remains**: a list of excluded constructs is only complete if someone enumerated both grammars.

**What is false, in the tree now:**

- Validation Rule Registry 1.5.0: *"~~Not every divergence is closed (1.4.1).~~ **Closed in 1.5.0**"*. Only case folding is admitted as a limit.
- `validation.ts:158–163`: *"A definition carrying a construct the two engines read differently … is refused by the server when it is saved, so a pattern that reaches this function is one both sides agree about."*
- `validation.rs:154–157`: *"a pattern reaching this arm is one both sides agree about."*
- The scan's own boundary, in `divergent_construct`'s doc: the *Not covered* list names case folding only.

**Why not blocking.** Nothing regressed. Every row above was stored before #451 too, and #451 strictly narrowed what diverges. What is wrong is the claim of completion, in the registry an author reads. **It is filed `sprint:19` because `v0.8.0`'s notes will be written from those texts.**

**For the release run, not a finding.** `publish_form` re-validates the **stored** definition (`rad/service/form.rs:253–262`). A form stored under `v0.7.0` with `\b`, `[[:digit:]]` or `\p{…}` cannot be published after `v0.8.0`, so a title-only revision gives a draft that cannot be published. That is record 15 finding 2's situation exactly. `[Unreleased]` has no entry for #451 yet, and the release's upgrade notes have to say it.

### Finding 3: every negated class is refused with its positive class's reason and remedy. **Not blocking. [#466](https://github.com/sujanto-gaws/kelir/issues/466).**

**`^\D+$` is told to write `[0-9]`.** #413 was filed because one message served three classes and was wrong for one. #451 split the message by construct, but `divergence_reason` matches `'d' | 'D'`, `'w' | 'W'` and *everything else* as `\s`. What the save seam returned in P1:

| Pattern | The message says | The case |
|---|---|---|
| `^\D+$` | *"`١٢٣` fails in the browser and passes here. Write the class out: `[0-9]`"* | `١٢٣` **passes** in the browser and **fails** here. `[0-9]` is the complement of `\D` |
| `^\W+$` | *"Write the class out: `[A-Za-z0-9_]`, which is what the browser was already doing"* | The browser was doing `[^A-Za-z0-9_]` |
| `^\S$` | *"Write out the characters this field should treat as space"* | `\S` is non-space |
| `caf\B` | *"`caf\b` matches `café` …"*, remedy `(^\|[^A-Za-z0-9_])` | A remedy for a boundary, sent for a non-boundary |
| `^\p{Nd}+$`, `params.flags` `u` | *"ECMA-262 reads `\p{…}` only under the `u` flag, **which this rule does not carry**"* | The rule carries it. Under `u` both engines read `\p{Nd}` as Unicode `Nd`, so a portable pattern is refused for a false reason: `divergent_construct` ignores flags |

`each_character_class_is_refused_with_its_own_reason` sends `\d`, `\w` and `\s`, so none of these rows is tested. **Not blocking**: every refusal is right to refuse, apart from the `u` row, and the harm is the wrong advice.

## 4. What was read and cleared

- **The overdue widget's exclusions hold, one move at a time (P5).** Five late tasks were on one holder's widget with `tasksOverdue` 5. Soft-deleting the document, soft-deleting the task, cancelling it, moving it to another tenant and expiring the holder's queue grant each took one task off, and the count fell 4, 3, 2, 1, 0. These cases are one `WHERE` shared with the inbox, so the result is expected. It is now measured rather than inferred. The committed tests already cover an undated task, a completed late task, another holder, department scoping and delegation.
