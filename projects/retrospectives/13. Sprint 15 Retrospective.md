## What Worked

**All seven of the last retrospective's actions closed, and five of them closed because they were scope.** [Retrospective 12](12.%20Sprint%2014%20Retrospective.md) produced seven actions; five became rows in this sprint's plan, two were discharged by the act of planning, and none sat below the cut line. That is the first time any of those three things has been true. **The mechanism is not mysterious**: retrospective 12 observed that the actions which close are the ones naming an artefact, and this sprint went one step further by making them *items*. An action that is scope gets built.

**The cut line was walked at the boundary, by the sprint that owns it.** Row 7 ([#348](https://github.com/sujanto-gaws/kelir/issues/348)) was built rather than dropped, and `gh issue list --label sprint:15` returns seven closed and none open. The last two sprints put rows below the line and then built them afterwards, on request — this is [retrospective 11](11.%20Sprint%2013%20Retrospective.md)'s seventh action finally working where it was meant to.

**Positioning a decision on the sequence worked, on a question a plan cannot answer.** [Construction plan 11](../planning/11.%20Sprint%2015%20RAD%20Authoring%20Construction%20Plan.md) §7 step 2 put **D-66** in week one rather than at the exit, saying plainly that *a plan cannot answer a question reserved to the product owner; it can refuse to let the answer arrive too late to act on*. It was answered on 2026-09-08, the day the plan was adopted — **the first time either of the two twice-carried rules has fired on schedule** — and [#335](https://github.com/sujanto-gaws/kelir/issues/335) then closed inside the same sprint, which had been impossible for two.

**Item 1's constraint held, and its position did not.** [Construction plan 11](../planning/11.%20Sprint%2015%20RAD%20Authoring%20Construction%20Plan.md) §4 put the report test first, arguing that *a control merged in the last week is a control that was never in force for the sprint that built it*, and §7 step 3 bound it to merge before the report it governs. **The binding half held** — it merged 2026-09-08, the report was written 2026-09-09. **The ordering half did not**: it merged *second*, 27 minutes after the form builder (12:42:38Z against 12:15:13Z).

**That cost nothing here, and it is worth recording because of why.** The plan expected item 3 to *run the length of the sprint*; had it done so, a control ordered behind it would have landed in exactly the last week §4 warned about. It did not, because the form builder came in at two fifths of the estimate — so **the sequencing was rescued by the estimate being wrong**, and the two findings are the same finding seen from opposite ends. Nothing checks a plan's stated order against the merge log, and nobody noticed until this report was written.

**Ordering item 4 before mid-sprint refinement was the sharper call.** Ten doc comments said *the mutation that must make this red is …*; all ten were run, nine reddened, and **two named symbols that do not exist**. Had a pass read that record as evidence, it would have been reading a materially weaker set of claims than it believed — which is precisely what §4 said the position was for.

**26 mutations run and 24 red — the most a sprint has run here, at a ratio slightly below the last one** (92% against Sprint 14's 96%, 24 of 25; Sprint 7's 37%; Sprint 6's 65%). **Both greens were findings rather than nuisances**, as [coding standard](../../docs/standards/01.%20Coding%20Standard.md) §2.9 says they should be, and both had the same cause: a fixture in which the two conditions coincided, so the mutation was *invisible* rather than absent. Neither was a wrong anchor.

**Two defects were found in in-flight code and fixed before merge, because the migration was still unmerged.** Item 7's reader claimed in two places that an absent `listId` returns *every action of this context*, when three-valued logic means it returns the tenant-wide rows alone; and its foreign key did not carry the tenant, leaving one tenant's action able to name another tenant's list. **A merged migration cannot be edited**, so the second would have cost a second migration had it been found a day later.

**Evidence by observation, where the API refuses to answer.** [#335](https://github.com/sujanto-gaws/kelir/issues/335) AC3 was written as *seen unable to merge* rather than as an API assertion, before anyone knew that `repos/…/branches/main/protection` answers `403` to this repository's own token. It turned out to be the only available route, and the probe found the thing a status string cannot show: GitHub reports `BLOCKED` to an administrator who can bypass exactly as to one who cannot, so **the absent override is the evidence and the blocked state is not**.

## What Didn't

**The independent pass did not run, for the eighth sprint, and this time nobody even asked.** There is no record 15 in [`projects/verifications/`](../verifications/). [Construction plan 11](../planning/11.%20Sprint%2015%20RAD%20Authoring%20Construction%20Plan.md) §7 step 6 put it on the sequence as a named event with a dispatcher, while stating in the same plan that *item 1 does not make it fire, and nothing in this plan can*. Both halves of that sentence proved correct.

**The capacity argument that set the line at six was wrong, in the direction it stated.** §3 cut the sprint from seven to six because *item 1 is larger than anything Sprint 14 built* — the form builder against Sprint 14's largest rows at 5,275 and 5,108 lines. **It came in at 2,117.** The sprint then built seven anyway by taking the row below the line, so nothing was lost; but the estimate that bought the reduction was not merely imprecise, it was inverted.

**Three of the four rows in [Product Backlog](../planning/02.%20Product%20Backlog.md) §6.2 were not open.** **D-39** and **D-40** were answered on 2026-08-28 and applied in `repository::task::holds_role` and `engine::fire`, and had sat for eleven days in a table headed *Open* with their resolutions written into the question column. **D-15** was four sprints old. The table was also malformed — those two rows carried two cells against a four-column header, D-15 three — **which is why nothing noticed**: a reader skims a table headed *Open* as a list of what is undecided, and three quarters of it was decided.

**[#274](https://github.com/sujanto-gaws/kelir/issues/274) is unscheduled for a fourth sprint, and it stopped being harmless this sprint.** It is an unexplained intermittent 500 in `master_data_party_roles`, inside `Backend (Rust)` — a job that has always been a required check and, since 2026-09-09, one nobody can bypass. **D-75** accepted that cost in writing rather than discovering it.

**The full backend suite could not be run in one pass locally on the first attempt.** MinIO had not started, because another project's stack held port 9000, and one attachment test failed with an S3 error 25 minutes into the run. **The failure was legible immediately** — the harness printed the S3 error under the failing test, which is what **D-59**'s log capture exists for — and [#386](https://github.com/sujanto-gaws/kelir/pull/386), merged in this same sprint, documents both traps. The documentation paid for itself inside a day, which is worth recording as the small good news it is.

## Root Causes

**The pass fails because every control this project has built enforces a *record*, not an *act*.** `adr_records_are_current.rs` makes a stale record fail; `sprint_reports_are_verified.rs` makes an unverified report say so; the migration-mapping table's own warning says a number maintained by remembering will eventually be wrong. All three are checks on artefacts that already exist. **A pass that never runs produces no artefact to check**, so no test of this shape can reach it. Item 1 was the right instrument aimed at the only part of the problem it could reach — the label — and the sprint proved that is not the same part. **The act needs a trigger outside the sprint's own goodwill**: something that blocks a thing the project wants, which at this point means the `v0.7.0` tag.

**The capacity estimate compared descriptions instead of comparables.** §3 reasoned that a form editor *authors a JFSS document: components, containers, sections, validation rules, calculation expressions, conditional logic, publish and revisions*, against a document type builder that *edits six fields and three foreign keys* — and concluded the first was larger. The feature descriptions were accurate and the conclusion was wrong, because **what drives the size of an admin screen here is how much of the shell already exists**, not how much the screen does. Sprint 14's builders paid for the shell; this sprint's inherited it. §8's *within-sprint* version of the same reasoning was correct — it predicted item 2 would be cheap once item 1 settled the shell, and item 2 came in at 1,375 against item 1's 2,117. **The model works inside a sprint and fails across sprints**, because across sprints nobody re-measures what was already paid for.

**§6.2 went stale because a decision's resolution is written where a reader will see it and nowhere a check can.** Whoever answered D-39 and D-40 did the substantive work — the reasoning is thorough, dated, and applied in code — and appended it to the question cell, which reads correctly to a person reading that row. The table's own closing paragraph already says answered decisions move to §6.1 with the date and what was applied where. **The rule existed, was known, and was not performed**, which is the same shape as the pass one level down: a convention with no artefact that fails.

## The sprint, in one paragraph

Sprint 15 did everything it planned, plus the row it had deliberately cut, and closed the two-sprint-old question about who the gate binds — and its own most interesting failure is that the estimate which justified cutting that row was wrong in the direction it stated, by a factor of two and a half. The construction is not in doubt: the form and list builders make true a sentence `v0.6.0` published about Phase 7, seven issues closed with none open, one migration, three decisions taken and three stale ones cleared, and 26 mutations run with 24 red — the most a sprint has run here, at a ratio a shade under the last one's. **What did not happen is the independent pass, for the eighth sprint, on the sprint that built the test which makes its absence unsayable.** That test is doing its job: this report and [status report 16](../status/16.%20Sprint%2015%20Status.md) both say plainly that nobody else read this sprint's work. But saying so is not the same as reading it, and the project now has three controls that enforce records and none that enforces an act. **The next instrument cannot be another test**, because the thing being checked does not exist to be checked; it has to be something the project wants — the `v0.7.0` tag — refusing to happen without it.
