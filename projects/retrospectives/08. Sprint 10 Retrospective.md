# Sprint 10 Retrospective — 2026-08-28

**Status:** Final · **Last updated:** 2026-08-28

**Sprint:** 10 (Phase 5, *Workflow Engine*) · **Goal:** a submitted document enters an approval it cannot leave by accident — a definition becomes a running instance, the instance generates the task, someone approves or rejects it, and the document's status follows from that rather than beside it.

Landed with the [status report](../status/11.%20Sprint%2010%20Status.md) and [record 07](../verifications/07.%20Sprint%2010%20Surface%20Verification.md), which is Sprint 5's rule 3.

## What Worked

- **Writing the plan's §7.1 before the engine, and then having only one engine.** `engine::fire` is the single path that moves a process; the submit and the decision both call it, and Sprint 11's return and delegate will call the same one. The plan said *an engine is the shape a codebase most easily grows two of* before a line was written, and that sentence is what stopped a second one appearing at the submit.
- **Three invariants are database constraints rather than habits.** An instance cannot be in a state its definition does not declare; a document cannot have two live processes; a process cannot have two open tasks. Each was a sentence in an acceptance criterion and each is now something a reader can check without reading the service — and two of the three have tests that reach the *constraint* rather than the service in front of it.
- **The type system refuses D-35's defect.** Every function on the engine path takes `&mut PgTransaction` and none takes `AppState`, so the two-connection deadlock this project wrote twice in Sprint 9 cannot be written here without changing a signature. That is the Sprint 9 action *"a fix for a rule violation is checked against the rule, over the whole unit"* applied preventively rather than after a finding.
- **Step 0 worked, and it is the first time it has.** The construction plan sequenced the carried findings ahead of item 1, and all three closed before any workflow code existed. Three sprints carried a similar item as an entry *criterion* and three sprints slipped it; the sprint that put it in the sequence did it.
- **Extracting the JWSS meta-schema found two defects in a document nobody had ever executed** (§*What Didn't*, F2 and F3). Both had been there since 2026-08-11.

## What Didn't

- **No second reader, for the second sprint running.** [Record 07](../verifications/07.%20Sprint%2010%20Surface%20Verification.md) §1 opens by disclaiming its own independence, as record 06 did. The Sprint 9 action *"an independent read of `modules/document/` happens in Sprint 10"* is **not done**, and neither is the plan's own exit clause. Every row of the status report reads `author-verified`.
- **A concurrent edit to the same working tree took this sprint's migration number**, and nothing detected it until forty integration tests went red at once with `duplicate key value violates unique constraint "_sqlx_migrations_pkey"` — a message four steps from the cause, on a harness banner that correctly says *this is a setup failure* and cannot say why.
- **Two normative artifacts were wrong in ways only execution could find.** The JWSS meta-schema `$ref`'d a schema file that has never existed, so no validator could ever have compiled it; and JWSS §6.2 forbids the operators JWSS §10's own worked example uses. Both survived from 2026-08-11 to the day something first tried to run them.
- **A submit answered `500` on a configuration two document types can fall into** — templates that render the same number. Found by a *fixture*, not by a reader: no test before this sprint had put two numbered types in one database.
- **The exit demo's environment cost was not on any plan.** Running it means building two release images and standing up a stack; the sprint plan treats "driven through the harness" as a property of the test rather than as work with a duration. It ran, and `deploy-local.sh` still could not complete: its smoke test compares `/version` against the tag it deployed, and a pre-release build's package version does not match its image tag.
- **The mutation campaign took four attempts.** Three were abandoned to linker contention with the concurrent worker — a failure with nothing to do with any mutation — before the fourth, given a build directory of its own, completed all 34 and produced **68%**, the highest this project has recorded. The one number [coding standard](../../docs/standards/01.%20Coding%20Standard.md) §2.9 asks a sprint for was nearly lost to a machine two workers were sharing.
- **Eleven predicates still survived, and eight are behind a gate.** Closing one finding created one of those gates. The measurement is better than it has ever been and it is still measuring the outermost layer of a stack that now has two.

## Root Causes

- **A normative artifact that nothing executes is a document, not a standard.** JFSS has an extracted meta-schema and a test that compiles it, and JFSS is the one standard in `docs/schema/` that has never been found internally inconsistent. JWSS, LHCS, PMS, EES and DTDS have embedded blocks that nothing has ever parsed. Two defects fell out of JWSS within an hour of the first attempt.
- **An action whose owner is the person it constrains cannot be done.** "An independent read happens in Sprint 10" was written by, assigned to, and executed by the same party. It is the third process action in this project to fail that way, and the two before it failed for the same reason rather than through carelessness.
- **A version number is a shared resource and nothing treats it as one.** `_sqlx_migrations`' primary key is the only thing that notices a collision, and it notices at the worst possible moment — after every test has already been written against the assumption.
- **A test that reaches a predicate through the layer in front of it measures the layer.** Eight of eleven greens are gates, and one of them was created by a fix landed this same sprint. The campaign is honest about the *outermost* guard and blind to everything behind it, which is exactly what §2.9 says a gate does — and this is the first record to have enough reds for the greens to be legible as a pattern.
- **A measurement that costs a rebuild per data point cannot survive a contended machine.** The campaign is 34 rebuilds of a crate that takes about a minute to link, and it shares `target/` with everything else. Nothing about its design accounts for that, and three runs died to it before the sprint had a number.
- **A second subject in a fixture finds defects the fixture was not written to find.** Coding standard §2.9's rule exists to make *scoping* assertions mean something. Here a second document type, added for that reason, found a 500 in a path nobody was testing.

## The sprint, in one paragraph

Phase 5 opened with the thing the four sprints before it were scaffolding for: a document that somebody else has to approve. What the sprint proved is that the project's own rules are now cheaper to follow than to break — the connection rule is a signature, the sequential-approval assumption is an index, and the one-engine rule is a call graph anybody can read. What it did not prove is anything a second reader would have found, for the second sprint running; nor, in the end, its own coverage ratio — the one number a sprint owes, lost to a machine two workers were sharing. The two most interesting defects it did find came from executing documents that had been read many times and run never.
