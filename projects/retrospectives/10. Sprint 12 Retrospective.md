# Sprint 12 Retrospective — 2026-08-31

**Status:** Final · **Last updated:** 2026-08-31

**Sprint:** 12 (Phase 6, *Attachments, Comments, Activity*) · **Goal:** a document stops being only a form and a decision — it carries the files it is about, the conversation around it, and a timeline that says what happened to it.

**Sprint outcome:** goal met, exit not closed · **Velocity note:** six items planned, six built, six merged; none cut, none added.

Landed with the [status report](../status/13.%20Sprint%2012%20Status.md), which is `Draft` and not `Final` — because the independent pass §2 requires has not happened, for the fourth sprint running. That is this retrospective's subject more than anything the sprint built.

---

## What Worked

- **The construction plan existed, and it was right about the thing that would have broken.** The [Sprint 11 retrospective](09.%20Sprint%2011%20Retrospective.md)'s first action asked for one; it found before a line was written that `activity_events` references `attachments` and `comments`, so the sprint plan's item order would have produced a migration that does not apply. **An ordering defect caught at planning costs a paragraph; caught in week two it costs the sprint's last item.**
- **Two rules were moved out of prose and into the type system**, and both were tested by trying to break them. `activity::record` takes a transaction where `audit::record` takes a pool, so the audit-shaped version **does not compile**; `scanner::scan` returns `Result<ScanOutcome, ScanError>`, so *the scanner did not answer* cannot be pattern-matched into a status. A rule a signature holds is one the next caller cannot step around, which is the Sprint 10 retrospective's observation applied twice more.
- **The mutation campaign found something no test had.** Dropping the `PENDING` predicate from the scan write left every test green — a guard behind another guard, reached by nothing. That is exactly what §2.9's campaign is for and the first time this project's campaign has produced a *finding* rather than a ratio.
- **The scanner was measured before it was built.** **D-4** chose ClamAV on 2026-08-11 and sized nothing; 25 MiB scans in ~169 ms, ~1 GB resident, no gain from concurrency. The measurement also found that `clamdscan` on a shared filesystem answers `OK` where the wire answers `ERROR` — so a worker built the obvious way would have recorded *clean* exactly where a stream is refused.
- **The exit demo paid for itself in its first ten minutes**, twice over. See *What Didn't*.

## What Didn't

- **No independent pass, for the fourth consecutive sprint.** Sprints 9, 10 and 11 closed the same way. Sprint 11's was rescued by a phase boundary; there is no boundary here, and Sprint 13 carries the MVP. The construction plan §15 named the decision that would break the run — **a party and a date, set at planning** — and recorded that it could not take it. Nobody took it, and nothing in the plan made anyone.
- **The deployed stack could not run three of this sprint's six items**, and every test was green. `deploy/staging/docker-compose.staging.yml` gave the backend `KELIR_STORAGE_DRIVER: s3` and nothing else: no endpoint, no bucket, no scanner. The `clamav` service went into the *development* compose with #246 and not into the one CI deploys and §2's environment clause names.
- **And then the bucket was never created, because of a YAML folded scalar.** `>-` folds lines into spaces *except* more-indented ones, which it keeps literal — so `minio-init`'s command reached the container as three shell commands, ran `mc alias set` with no credentials, tried to execute the username and the password, and **exited 0**. The same defect sat in the development compose, unexercised only because that bucket had been created by hand.
- **The verification allowance was not spent at all.** It opened holding five findings, gained three, and closed **none**. Sprint 11 filed six and closed six.
- **The exit criterion cannot be met as written**, and could not have been by anything this sprint did: it asks for a browser demonstration of a feature set the plan deliberately gave no screens. That is the [Sprint 8 retrospective](06.%20Sprint%208%20Retrospective.md)'s second action recurring **four** sprints later.
- **The commit-header rule was met by hand every time and still nearly missed.** #290's header would have squashed to 77 characters; it was caught while writing the pull request, not by anything that checks.

## Root Causes

- **A rule with no owner and no date does not fire, and four sprints is enough evidence to stop calling it a lapse.** §2 makes the pass a condition on `Done`; it names nobody and no day. The one pass in this project's history that ran on time was Sprint 9's **mid-sprint** pass, which had a fixed date set at planning. Everything else happened when a boundary forced it or not at all. **The rule is not failing to be followed; it is failing to be actionable**, and the honest options are the two Sprint 10's retrospective already put: give it an owner, or say what a self-pass is worth and let `author-verified` be the expected label.
- **A test configures its own environment, so no test can see a deployment.** Every unit and integration test in this suite sets the storage endpoint, the bucket and the scanner address it wants. The deployment is the one artefact nothing reads, and it was wrong in three independent ways. **The only thing that looked at it was the exit demo**, which is the entire argument for that criterion existing — and which this project has now run twice, finding a defect both times.
- **A `command:` that exits 0 is not a command that worked.** `minio-init` reported success while doing nothing, because a shell that cannot find a command still exits 0 if the last one succeeded. A one-shot container's job is to make a postcondition true, and nothing checked the postcondition — the backend discovered it, four steps later, as `NoSuchBucket`.
- **An allowance is spent when the findings arrive early, and these arrived last.** Sprint 11's six were filed *during* its close, when there was still a close to fix them in. This sprint's three arrived from a read performed after the last item merged, and the five it inherited were never scheduled at all — they sat behind six construction items with nothing pulling them forward.
- **An exit written before the scope is decomposed describes the wrong thing.** Sprint 12's exit sentence was written at Phase 6 planning, before the construction plan established that no UI was in scope. By the time the two disagreed, the sentence was a criterion and nobody re-read it against the plan below it.

## The sprint, in one paragraph

Sprint 12 built everything it planned, merged all of it, and closed nothing. The six items are the collaborative half of a document — its files, its conversation, its history — and the type system now carries two of the rules that matter most, which is the best thing in the sprint. The worst is that the deployment those items ship in could not run three of them, and that no test in eleven hundred could have told anybody: it took an exit demo, the one criterion this project keeps treating as a formality, ten minutes to find two defects that would have made attachments non-functional in front of a user. The pass that would have looked for the rest has not happened for the fourth sprint running, and the plan that was supposed to force it recorded that it could not. Sprint 13 carries the MVP.
