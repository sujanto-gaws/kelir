## Migration review

**Two migrations since `v0.7.0`, sequential from `0042` with no gaps.** Both are commented at length on their own N−1 half.

| Migration | What it does | N−1 |
|---|---|---|
| `0043_reporting.sql` | Creates `idx_documents_tenant_id_created_by_status`, inserts the `reporting:dashboard:read` permission and grants it to `ROLE-ADMIN` | **Additive.** An index `v0.7.0` never names, and a permission row it reads as catalogue and checks in no route |
| `0044_recent_documents.sql` | Creates `idx_activity_events_tenant_id_actor_user_id_created_at` | **Additive.** An index `v0.7.0` names in no statement |

**No table, column, constraint or data changes.** Record 17 P5 already ran `0044`'s N−1 half against the real `kelir-backend:0.7.0` image. **This run rehearses both migrations, both halves, on the release images**, because release process §6 says the rehearsal is the evidence and reading is not.

**The upgrade note on both is new, not a correction.** Each is a plain `CREATE INDEX`, which blocks writes to its table while it builds, and the backend migrates as it starts. `[0.8.0]` says so.
