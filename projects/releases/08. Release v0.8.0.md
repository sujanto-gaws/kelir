### §6 step 3: the compiled check, run and controlled

**`v0.7.0`'s source, every target including its tests, type-checks against the `0044` database**: `cargo check --all-targets` with `SQLX_OFFLINE=false`, **exit 0**, from a detached worktree at `v0.7.0`.

**Controlled, because a green compile proves nothing unless the macros reached the schema.** Against an **empty** database the same source went **red first: exit 101, 605 error lines, `relation "activity_events" does not exist`**. The crate was cleaned, and then the `0044` database gave **exit 0**. Every statement `v0.7.0` holds type-checks against the schema this release leaves behind.

### The rollback, with rows, and forward again

| Step | Result |
|---|---|
| The `0.8.0` stack, upgraded from a populated `v0.7.0` database (*The upgrade rehearsal*), then its harness run on it | 37 documents, 17 workflow instances, 81 activity events, 21 forms, 6 lists |
| **`deploy-local.sh 0.7.0 8091`**, the rollback command `deploy.sh` prints | **Exit 0.** `/version` and **`/version.json` both `0.7.0` and `2bd2e4a`**, with no *unverified* line. **[#440](https://github.com/sujanto-gaws/kelir/issues/440)'s fix, exercised on the first target that emits the file**, so both artefacts were checked, not one. | **`v0.7.0`'s own harness on that database** | **20 of 21.** `build-a-list` saved a new document type and did not find its row: the snapshot reads *Page 1 of 2*, and the database holds 28 types against a page of 20. The type was saved. No `WARN` or `ERROR` |
| **The control: forward again to `0.8.0`**, with `0.8.0`'s harness on the same database | Deploy exit 0, `/version` and `/version.json` `0.8.0` and `cdb3f55`. **23 of 24, the same spec failing the same way**: *Page 1 of 2*, 40 types. **The failure this row asks to be recorded.** `build-a-list.spec.ts:109` assumes a new document type appears on the list's first page. CI and the smoke pass start from an empty database, where it does. A rehearsal that runs a harness twice on one database does not. **Reproduced on both releases** and filed as [#503](https://github.com/sujanto-gaws/kelir/issues/503). It holds nothing: the rollback's evidence is the exit code, both identities, the counts and the 20 specs that passed, and the one that did not was shown not to depend on the release.
