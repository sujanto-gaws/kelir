# Release Checklist Template

**Status:** Template · **Last updated:** 2026-09-12

**Copy everything below the divider — not this file — into `NN. Release vX.Y.Z.md`** (continuing the folder's numbering) when cutting a release. The [release process](../../docs/standards/04.%20Release%20Process.md) is the authority on *how* each step is performed — this checklist records the *evidence* that it was, per release. Every roadmap phase ends with at least one tagged release.

> **The instruction used to say "copy this file", and that was a trap** ([record 15](../verifications/15.%20Sprint%2016%20Independent%20Pass.md) §7 finding 8, [#412](https://github.com/sujanto-gaws/kelir/issues/412)). This preamble carries a `**Status:**` line of its own, so a copy made by following it word for word had **two**: this one, saying `Template`, and the release's, further down. `releases_are_independently_verified.rs` reads the first — so a record could be set to `Final`, cite nothing, and pass every rule, while the reader saw a header that said `Final` and the gate read one that said `Template`. **The record was governed by nothing and nothing said so.**
>
> The gate now refuses both halves of that — a release record states its status **once**, and states one of the two words below — so a copy made the old way is red rather than silent. This line is the fix; that rule is the backstop.

---

# Release vX.Y.Z — <YYYY-MM-DD>

**Status:** Draft · **Last updated:** <YYYY-MM-DD>

**Phase:** <SDD §14 phase this release closes, or "hotfix"> · **Release manager:** <name>

## Pre-flight

| Step | Check | Evidence |
|---|---|---|
| **Independent pass** | **A verification record for work in this release exists in [`projects/verifications/`](../verifications/) and is cited in this record — one numbered above every record any earlier release cited.** The link must resolve. Held by `releases_are_independently_verified.rs`, so a record cannot go `Final` without it (§2, [#392](https://github.com/sujanto-gaws/kelir/issues/392), [#412](https://github.com/sujanto-gaws/kelir/issues/412)) | <record link> |
| Scope verified | All committed FR IDs traceable and verified (`requirements-analyst`) | <report link/path> |
| Tests green | Full suite passes in CI, including integration and E2E (`test-engineer` sign-off) | <CI run> |
| Migration review | Migrations sequential, no gaps; apply cleanly to (a) empty DB and (b) previous release's schema; N−1 compatible (release process §6) | <verification note> |
| Docs current | Consistency and schema gates pass; `Last updated` dates and `docs/README.md` index current | <audit result> |
| Version determined | From commit log per release process §1; `Cargo.toml` + `package.json` bumped in one `chore(release): vX.Y.Z` commit | <commit> |
| OpenAPI current | Spec regenerated and matches the API surface | <artifact> |

> **The independent-pass row is the one step here that a test holds rather than a person.** Every other row in this table is checked by whoever runs the release; that one is checked by `releases_are_independently_verified.rs`, which reads this record and refuses a `Final` one that cites no new verification record.
>
> **Why it is at the release and not at the sprint.** [Sprint plan](../planning/01.%20Sprint%20Plan.md) §2 has asked for a pass at every sprint's mid-sprint refinement since 2026-09-04 and has never once got one — eight sprints, eight failures. The requirement was moved to the place the project cannot skip. **It fires once per phase rather than once per sprint, which is less than §2 asks and more than §2 has delivered**, and §2 now says so rather than restating the rule a ninth time.
>
> **Why "numbered above every record any earlier release cited" rather than "one no earlier release cited".** The weaker wording was the rule until 2026-09-12, and [record 15](../verifications/15.%20Sprint%2016%20Independent%20Pass.md) §7 finding 7 showed what it left open: `projects/verifications/` held fifteen records and **eight of them had been cited by no release at all**, so *new to every release* was satisfiable by reaching into a pool of old readings. `v0.7.0` could have closed citing record 12 — a Sprint 12 read of work that shipped in `v0.6.0` — and the gate would have agreed. **The pool grows every time a sprint writes a record no release cites.** Records are numbered in the order they are written, so a number above the high-water mark is a reading that did not exist when the last release closed. It holds against all five governed releases: `v0.3.0` → 03; `v0.4.0` → 06; `v0.5.0` → 09, 10; `v0.6.0` → 13, 14; `v0.7.0` → 15.
>
> **The link must resolve, and that is a new rule rather than an obvious one.** Until 2026-09-12 the gate matched the *shape* of a citation and never opened the file, so a record citing `99.%20A%20Pass%20That%20Was%20Never%20Written.md` passed — a novel string counted as a new pass by being novel (finding 3, door A). **This is not a hypothetical evasion; it is what a typo in a hand-typed percent-encoded path does**, and every citation in this folder is hand-typed.
>
> **`Draft` is where a release run lives while it is worked, and `Final` is where it ends. Those are the only two statuses a release record may state.** The gate is on `Final`, so the checklist can be filled in with the pass still outstanding; what it cannot do is close.
>
> **This template said three different things at once until 2026-09-12**, and [record 15](../verifications/15.%20Sprint%2016%20Independent%20Pass.md) §7 finding 8 is the reading that noticed: this line said `Draft`, the specimen header above said `In progress`, and [record 07](07.%20Release%20v0.7.0.md) — the first record written under the gate — used `Draft`. **`In progress` was borrowed from the wrong vocabulary.** It is [sprint plan](../planning/01.%20Sprint%20Plan.md) §2's word for a sprint item whose author is also its only verifier, which is a judgement about a piece of work rather than a stage of a release run. The specimen was corrected to this line rather than the other way round, because practice and the gate already agreed with this line.
>
> **The vocabulary is now checked rather than described.** A header status the gate does not recognise used to leave the record governed by no rule at all — one character, a `|` where the house `·` goes, and a shipped release stepped outside the gate with every test green (finding 3, door C). An unrecognised status is now a failure that names the record.

## Aftermath

- **Issues found post-release:** <none / list, with hotfix decisions per release process §5>
- **Follow-ups filed:** <items carried into the sprint plan. **Every row states `reproduced` or `only observed`** — see below>
  - `<#NNN — what it is>` · **reproduced** · <which guard was bypassed>
  - `<#NNN — what it is>` · **only observed** · <the mechanism, as the hypothesis it is> · **to reproduce:** <what somebody would do first>

> **A follow-up filed from a release run says whether its mechanism was *reproduced* or *only observed*.** One of the two words, on every row.
>
> **`reproduced`** — somebody made it happen again and knows which guard was bypassed. **`only observed`** — it was seen once, during a run whose purpose was something else, and the mechanism written beside it is a hypothesis. **An `only observed` row also says what would reproduce it**, so whoever picks it up starts from the gap rather than from the conclusion.
>
> **[#361](https://github.com/sujanto-gaws/kelir/issues/361) is the case that earned this rule.** [Record 06](06.%20Release%20v0.6.0.md)'s Aftermath recorded that `deploy-local.sh` exited 0 on a run where Caddy never started. It became a row in the [sprint plan](../planning/01.%20Sprint%20Plan.md), then an issue — and when somebody finally went to fix it, **the mechanism did not hold**: `docker compose up -d` exits 1 on a port collision and `deploy.sh` carries `set -euo pipefail`, so that run should have aborted at the command described. The **observation** was real and remains so; the stack had no ingress and the script reported success. The **mechanism** was a reasonable guess written in the same voice as the observation, and by the time anybody read it the two were indistinguishable. [#368](https://github.com/sujanto-gaws/kelir/pull/368) shipped against a different hypothesis entirely — that `KELIR_PUBLIC_URL` is an address rather than a container, so a *previous* deployment on that port satisfies every assertion the smoke test makes.
>
> **A release run is where this is hardest and matters most.** Attention is on the tag, the finding is a distraction from it, and the note is written quickly and correctly — as an observation. The word is what stops the next reader promoting it to a diagnosis.
>
> **Record 06 is not amended**, and neither is any settled record. It said what was seen, under a template that did not ask this question. The correction belongs here, where the next release will read it.

Set this document's header status to `Final` when the release is verified in production.

> **The status word is written out here rather than quoted with its label, and the reason is worth two
> minutes.** `releases_are_independently_verified.rs` **decided whether a release record was governed by
> asking whether its body contained the header string**, so a record quoting that string anywhere —
> including in a sentence about what to do at the end — **enrolled itself in the gate before the release
> happened**, and then failed rule 2 against citations it was only listing. This line is where every copy
> of this template got that sentence.
>
> **The template escaped its own trap and its copies did not.** The walk reads a version out of the file
> name; `00. Release Checklist Template.md` has none and is skipped, while every copy is
> `NN. Release vX.Y.Z.md` and is not. **The defect was invisible in the file that carried it and sprang in
> the file made from it.** Four releases passed over it for a plainer reason: this line had been here since
> 2026-08-11, and all four were `Final` before the gate landed on 2026-09-09, so none of them was ever a
> `Draft` under it ([record 15](../verifications/15.%20Sprint%2016%20Independent%20Pass.md) §7).
>
> **Seen red, 2026-09-10**, on the first record that copied this line: restoring the quoted string to
> [record 07](07.%20Release%20v0.7.0.md) reddened `each_release_brings_a_pass_no_earlier_release_cited`,
> naming that record and all six citations it was making.
>
> **The detector has since been fixed at the root** ([#407](https://github.com/sujanto-gaws/kelir/pull/407)):
> it reads the status off the line that *is* the header, so a record may now quote the rule, explain the
> gate, or carry a note like this one, and only the header decides. **This line stays written out anyway.**
> The template is the one file whose text is copied into every future record, and a document should not have
> to be careful about which strings it contains for a control to read it correctly.
>
> **And the root fix was not the end of it** ([#412](https://github.com/sujanto-gaws/kelir/issues/412), 2026-09-12).
> [Record 15](../verifications/15.%20Sprint%2016%20Independent%20Pass.md) attacked the fixed detector with
> synthetic records and walked through it three more ways — a citation that resolves to nothing, a file name
> the walk could not parse, and a separator one character off the house one — plus two the §7 re-read found,
> including this preamble's own second header line. **Each fix so far had closed one instance rather than the
> class**, which is the point that note makes and the reason it is worth reading twice: *a control that reads
> a document is a control a document can trip.* The gate is now nine rules and twelve tests, each one seen
> red against the record that defeated its predecessor, with the honest case run last to prove the gate still
> lets a real release through.
