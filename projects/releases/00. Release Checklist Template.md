# Release Checklist Template

**Status:** Template · **Last updated:** 2026-09-11

Copy this file to `NN. Release vX.Y.Z.md` (continuing the folder's numbering) when cutting a release. The [release process](../../docs/standards/04.%20Release%20Process.md) is the authority on *how* each step is performed — this checklist records the *evidence* that it was, per release. Every roadmap phase ends with at least one tagged release.

> **The independent-pass row is the one step here that a test holds rather than a person.** Every other row in this table is checked by whoever runs the release; that one is checked by `releases_are_independently_verified.rs`, which reads this record and refuses a `Final` one that cites no new verification record.
>
> **Why it is at the release and not at the sprint.** [Sprint plan](../planning/01.%20Sprint%20Plan.md) §2 has asked for a pass at every sprint's mid-sprint refinement since 2026-09-04 and has never once got one — eight sprints, eight failures. The requirement was moved to the place the project cannot skip. **It fires once per phase rather than once per sprint, which is less than §2 asks and more than §2 has delivered**, and §2 now says so rather than restating the rule a ninth time.
>
> **`Draft` is where a release run lives while it is worked.** The gate is on `Final`, so the checklist can be filled in with the pass still outstanding; what it cannot do is close.

## Aftermath

- **Issues found post-release:** <none / list, with hotfix decisions per release process §5>
- **Follow-ups filed:** <items carried into the sprint plan. **Every row states `reproduced` or `only observed`** — see below>
  - `<#NNN — what it is>` · **reproduced** · <which guard was bypassed>
  - `<#NNN — what it is>` · **only observed** · <the mechanism, as the hypothesis it is> · **to reproduce:** <what somebody would do first>

> **A follow-up filed from a release run says whether its mechanism was *reproduced* or *only observed*.** One of the two words, on every row.
>
> **`reproduced`** — somebody made it happen again and knows which guard was bypassed. **`only observed`** — it was seen once, during a run whose purpose was something else, and the mechanism written beside it is a hypothesis. **An `only observed` row also says what would reproduce it**, so whoever picks it up starts from the gap rather than from the conclusion.
>
> **[#361](https://github.com/sujanto-gaws/kelir/issues/361) is the case that earned this rule.** [Record 06](06.%20Release%20v0.6.0.md)'s Aftermath recorded that `deploy-local.sh` exited 0 on a run where Caddy never started. It became a row in the [sprint plan](../planning/01.%20Sprint%20Plan.md), then an issue — and when somebody finally went to fix it, **the mechanism did not hold**: `docker compose up -d` exits 1 on a port collision and `deploy.sh` carries `set -euo pipefail`, so that run should have aborted at the command described. The **observation** was real and remains so; the stack had no ingress and the script reported success. The **mechanism** was a reasonable guess written in the same voice as the observation, and by the time anybody read it the two were indistinguishable. [#368](https://github.com/sujanto-gaws/kelir/pull/368) shipped against a different hypothesis entirely — that `KELIR_PUBLIC_URL` is an address rather than a container, so a *previous* deployment on that port satisfies every assertion the smoke test makes.
>
> **A release run is where this is hardest and matters most.** Attention is on the tag, the finding is a distraction from it, and the note is written quickly and correctly — as an observation. The word is what stops the next reader promoting it to a diagnosis.
>
> **Record 06 is not amended**, and neither is any settled record. It said what was seen, under a template that did not ask this question. The correction belongs here, where the next release will read it.

Set this document's header status to `Final` when the release is verified in production.

> **The status word is written out here rather than quoted with its label, and the reason is worth two
> minutes.** `releases_are_independently_verified.rs` **decided whether a release record was governed by
> asking whether its body contained the header string**, so a record quoting that string anywhere —
> including in a sentence about what to do at the end — **enrolled itself in the gate before the release
> happened**, and then failed rule 2 against citations it was only listing. This line is where every copy
> of this template got that sentence.
>
> **The template escaped its own trap and its copies did not.** The walk reads a version out of the file
> name; `00. Release Checklist Template.md` has none and is skipped, while every copy is
> `NN. Release vX.Y.Z.md` and is not. **The defect was invisible in the file that carried it and sprang in
> the file made from it.** Four releases passed over it for a plainer reason: this line had been here since
> 2026-08-11, and all four were `Final` before the gate landed on 2026-09-09, so none of them was ever a
> `Draft` under it ([record 15](../verifications/15.%20Sprint%2016%20Independent%20Pass.md) §7).
>
> **Seen red, 2026-09-10**, on the first record that copied this line: restoring the quoted string to
> [record 07](07.%20Release%20v0.7.0.md) reddened `each_release_brings_a_pass_no_earlier_release_cited`,
> naming that record and all six citations it was making.
>
> **The detector has since been fixed at the root** ([#407](https://github.com/sujanto-gaws/kelir/pull/407)):
> it reads the status off the line that *is* the header, so a record may now quote the rule, explain the
> gate, or carry a note like this one, and only the header decides. **This line stays written out anyway.**
> The template is the one file whose text is copied into every future record, and a document should not have
> to be careful about which strings it contains for a control to read it correctly.
