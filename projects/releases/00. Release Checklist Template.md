# Release Checklist Template

**Status:** Template · **Last updated:** 2026-08-11

Copy this file to `NN. Release vX.Y.Z.md` (continuing the folder's numbering) when cutting a release. The [release process](../../docs/standards/04.%20Release%20Process.md) is the authority on *how* each step is performed — this checklist records the *evidence* that it was, per release. Every roadmap phase ends with at least one tagged release.

## Release build

> The environment is the Docker Compose stack brought up from the release images
> (`deploy/staging/deploy-local.sh`), not a staging host: there is none, and none
> is scheduled. Decision **D-9** replaced the staging steps rather than waiving
> them — the property being checked is that what ships is what was verified.

| Step | Check | Evidence |
|---|---|---|
| Stack up from release images | Immutable images, migrations run by the backend at startup, nothing built from the working tree | <image digest / compose log> |
| Smoke pass | Canonical E2E scenario green against that stack; `/version` reports the released version and SHA | <run link> |
| Rollback rehearsed | Previous image boots against migrated schema — both halves of the N−1 rule, by the procedure in [release process](../../docs/standards/04.%20Release%20Process.md) §6. Record a failure here rather than leaving it blank | <note> |
