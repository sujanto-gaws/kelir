# ADR-0006 — Metadata-Driven Forms and Lists

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-04 (founding) · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** [ADR-0005](0005.%20An%20Internal%20Workflow%20Engine%20Instead%20of%20BPMN.md), [ADR-0008](0008.%20One%20JSON%20Logic%20Engine%20on%20Both%20Sides.md), [ADR-0014](0014.%20Kelir%20Extends%20JFSS%20Through%20Settings.md), [ADR-0015](0015.%20Calculations%20Run%20Before%20Conditional%20Stripping.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from [architectures/01](../01.%20Basic%20Framework%20Concept%20and%20Architecture.md) §29 Decision 6. The operative specifications are [JFSS](../../schema/JSON%20Form%20Schema.md) and the [Document Type Definition Schema](../../schema/Document%20Type%20Definition%20Schema.md) (standard §9).

Kelir's purpose is building enterprise business applications rapidly. The alternative to metadata is code: each new document type would be a form component, a list view, a validation function and a migration, written and released by whoever maintains the product.

## 2. Decision

**A form is a JFSS document, a list is a list definition, and both are rendered dynamically from metadata.** An administrator configures a document type — its form, its list, its workflow, its numbering — without a code change or a release.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. Metadata-driven, JFSS-defined** | Definitions in the database, rendered at run time | **Chosen** |
| B. Hand-written forms per document type | Ordinary components and endpoints | Rejected — new applications would ship at the product's release cadence, not the tenant's |

### A. Metadata-driven — chosen

New business applications can be created faster, an administrator can configure document types, the UI renders forms dynamically, and a workflow attaches to a document type (architectures/01 §29). This is the framework claim the product is built on; refusing it would leave a document management system rather than a RAD framework.

### B. Hand-written surfaces

Rejected at the founding pass. It remains true for the six core master-data entities, which have explicit typed endpoints for a different reason ([ADR-0007](0007.%20Explicit%20Endpoints%20for%20Core%20Master%20Data.md)) — the two are not in conflict: the core entities are platform-defined, the document types are tenant-defined.

## 4. Consequences

**Positive** — a document type is data, so it can be created, revised and versioned in the product rather than in a repository.

**Negative** — everything the compiler would have checked now has to be checked at run time, and every one of those checks became a decision: an expression language and one engine on both sides ([ADR-0008](0008.%20One%20JSON%20Logic%20Engine%20on%20Both%20Sides.md)), the order the server re-evaluates in ([ADR-0015](0015.%20Calculations%20Run%20Before%20Conditional%20Stripping.md)), what a rule this build cannot enforce does ([ADR-0016](0016.%20An%20Unenforceable%20Rule%20Refuses%20Rather%20Than%20Passes.md)), what a division by zero means ([ADR-0018](0018.%20Division%20by%20Zero%20Is%20an%20Evaluation%20Error.md)), and how the product extends a frozen standard ([ADR-0014](0014.%20Kelir%20Extends%20JFSS%20Through%20Settings.md)). **The Tamper-Proof Pattern follows from this decision**: because the client computes, the server must recompute and overwrite (JFSS S8.1), or a total is whatever the browser says it is.

**Neutral** — a form's data is tenant-authored JSON whose keys the platform does not know, which is why an audit record of a form-data change names keys and not values (`D-32`, [ADR-0011](0011.%20A%20Derived%20Surface%20Requires%20the%20Permission%20of%20What%20It%20Derives%20From.md)).

## 5. Compliance

A definition is validated against the JFSS meta-schema at save (`validate_definition`), and the meta-schema file is compared byte-for-byte with the specification's fenced block by `rad_jfss_meta_schema.rs` — a specification describing a schema the product does not enforce is worse than no specification.

## 6. Revisit When

The configuration surface stops being able to express what tenants ask for without a code change anyway — at which point the metadata layer is paying its cost without buying its benefit.
