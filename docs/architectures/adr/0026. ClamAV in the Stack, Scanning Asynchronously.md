# ADR-0026 — ClamAV in the Stack, Scanning Asynchronously

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-11 · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** `D-4`, [ADR-0003](0003.%20PostgreSQL%20as%20the%20Only%20Database.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from `D-4` in [Product Backlog](../../../projects/planning/02.%20Product%20Backlog.md) §6.1; the operative statement is [Database Schema](../../design/02.%20Database%20Schema.md) §8.1 (standard §9).

Attachment virus scanning (FR-ATT, Phase 6) had no chosen scanner. Two questions came with it: which scanner, and whether a scan blocks the upload.

## 2. Decision

**ClamAV, as a service in the compose stack, scanning asynchronously.** Upload sets `virus_scan_status = PENDING`, a worker updates it via the outbox, and **download is blocked until `CLEAN`**.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. ClamAV in the compose stack, async scan, download gated** | Self-hosted, no per-file cost | **Chosen** |
| B. A hosted scanning API | Less to run | Rejected — an external dependency and a per-file cost, and it sends tenant file content off-site |
| C. Scan synchronously on upload | Simplest state machine | Not taken — upload would wait on the scanner; the `PENDING` → `CLEAN` states exist precisely so it does not |

### A. ClamAV — chosen

It matches the self-hosted stack already in `deploy/docker/docker-compose.yml`, adds no external dependency or per-file cost, and **keeps file content on-site** — which is the property that decides it for a product handling requisitions, contracts and personnel documents.

**The container joins the compose file in Sprint 12, not at the decision**: a scanner with no consumer would just slow every local stack.

## 4. Consequences

**Positive** — no third party sees tenant files; the cost is a container rather than a bill per upload.

**Negative** — ClamAV is a service a deployment has to run, resource it and keep current; its signature updates become an operational task. A file is downloadable only after a scan completes, so a large upload has a visible gap between "stored" and "available".

**Neutral** — the gate is a status column and an outbox consumer, so the same shape serves any future scanner: replacing ClamAV means replacing the worker, not the model.

## 5. Compliance

The download path refuses anything not `CLEAN`; that refusal is the enforcement and belongs to the attachment module's tests when the surface is built.

## 6. Revisit When

The scan queue's latency becomes the complaint rather than the safety — or a deployment requires a scanner it already licenses, which the outbox-and-status shape accommodates without a redesign.
