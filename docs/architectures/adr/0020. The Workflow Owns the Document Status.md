# ADR-0020 — The Workflow Owns the Document Status

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-28 · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** `D-36`, `D-46`, [ADR-0005](0005.%20An%20Internal%20Workflow%20Engine%20Instead%20of%20BPMN.md), [ADR-0019](0019.%20A%20Workflow%20Definition%20Is%20Narrowed%20at%20Save%20Time.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from `D-36` in [Product Backlog](../../../projects/planning/02.%20Product%20Backlog.md) §6.1; the operative statement is [SDD](../../design/01.%20System%20Design%20Document.md) §8.5.2 (standard §9).

Sprint 9 shipped `PUT /documents/{id}/status` behind its own permission, with a legality table and a compare-and-swap. Sprint 10 gave the same column a second writer: a workflow transition projects the state's `mapsToDocumentStatus` onto `documents.status`. #178 AC2 requires the synchronization to be **one-way** — a transition sets the status, and setting the status does not move the workflow — and left open what the existing manual route does about it.

Leaving both writers is a document whose status disagrees with the process deciding it, produced silently, on the screen a person is most likely to trust.

## 2. Decision

**`PUT /documents/{id}/status` refuses a document that has a live process instance, naming the instance.** The projection is one-way, and the route is where that is enforced. A document whose process has *finished* is transitionable again.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. Refuse the manual transition while a process is live** | One writer at a time, and the refusal says which | **Chosen** |
| B. Let the manual transition win | Keep the Sprint 9 capability whole | Rejected — makes the workflow a suggestion |
| C. Silently ignore it | Accept the call, change nothing | Rejected — the same outcome with no message |

### A. Refuse — chosen

A finished process is not a loophole: nothing is deciding the document, and the legality table is back to being the only rule. #178 AC2 allows for a manual override as *"a separate, audited action rather than a side effect"* — none is built, because nothing has asked for one and the refusal is what makes the need visible if anything does.

## 4. Consequences

**Positive** — the document's status has exactly one writer while a process runs, so the screen cannot show a status the process disagrees with.

**Negative, accepted** — this withdraws a capability the document surface shipped one sprint earlier, for documents of types that bind a workflow.

**Neutral, and later corrected elsewhere** — the sibling guard on *deletion* used `status = 'DRAFT'` as a proxy for *has no live process*, and `D-46` found the proxy false and replaced it with a read of `workflow_instances` under the row lock ([ADR-0019](0019.%20A%20Workflow%20Definition%20Is%20Narrowed%20at%20Save%20Time.md) §3 D). This decision's own check reads the instance directly and was never the proxy.

## 5. Compliance

`a_document_under_a_workflow_cannot_have_its_status_set_by_hand` in `workflow_engine.rs`. The refusal lives in `document::service::status` and names the instance, so the message itself distinguishes this from a permission failure.

## 6. Revisit When

An audited manual override is genuinely required — the case #178 AC2 anticipated — at which point it is a new action with its own permission and audit record, not a re-opening of the two-writer question.
