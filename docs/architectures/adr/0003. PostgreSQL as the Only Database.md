# ADR-0003 — PostgreSQL as the Only Database

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-04 (founding) · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** [ADR-0002](0002.%20SQLx%20with%20Compile-Time%20Verified%20Queries.md), [ADR-0006](0006.%20Metadata-Driven%20Forms%20and%20Lists.md), [ADR-0012](0012.%20The%20Audit%20Hash%20Chain%20Covers%20the%20Payload.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from [architectures/01](../01.%20Basic%20Framework%20Concept%20and%20Architecture.md) §29 Decision 3. The operative schema statement is [design/02. Database Schema.md](../../design/02.%20Database%20Schema.md), which wins every table and column question (authority rule 5).

Kelir stores three kinds of thing that pull in different directions: platform rows with fixed columns (users, roles, documents), tenant-authored JSON whose shape the platform does not know (form definitions, form data, workflow definitions), and an append-only audit trail that must be searchable and tamper-evident.

## 2. Decision

**Kelir runs on PostgreSQL, and only PostgreSQL.** JSONB carries the metadata-defined content; everything else is relational.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. PostgreSQL only** | JSONB, search, indexing, audit and document metadata | **Chosen** |
| B. MySQL/MariaDB support behind a compatibility layer | The portability SQLx would have allowed | Rejected for now — recorded as "can be added later", and the cost has grown since |

### A. PostgreSQL — chosen

Chosen for JSONB, better search, better indexing, and suiting audit and document metadata (architectures/01 §29). Every later decision has leaned on that: a document's form data is JSONB, an audit row's `old_value`/`new_value` are JSONB ([ADR-0011](0011.%20A%20Derived%20Surface%20Requires%20the%20Permission%20of%20What%20It%20Derives%20From.md)), and the numbering allocator is a single `INSERT … ON CONFLICT DO UPDATE … RETURNING` ([ADR-0022](0022.%20Numbering%20Counters%20Live%20in%20Per-Scope%20Buckets.md)).

### B. MariaDB behind a compatibility layer

The founding record kept it open — *"MariaDB support can be added later with compatibility layer"*. It is recorded here as rejected-for-now rather than open, because the price has been paid in the other direction ever since: partial and total unique indexes (`D-19`), `ON CONFLICT` upserts, `FOR UPDATE` / `FOR KEY SHARE` row locks (`D-30`, `D-46`) and JSONB predicates are all PostgreSQL-shaped, and compile-time query verification ([ADR-0002](0002.%20SQLx%20with%20Compile-Time%20Verified%20Queries.md)) binds each query to one dialect.

## 4. Consequences

**Positive** — one dialect to write, test and tune; the schema can use the features it needs without a portability check on every statement.

**Negative** — a deployment that mandates MySQL/MariaDB cannot run Kelir, and the compatibility layer the founding record imagined would now be a substantial project rather than an adapter. The 2026-08-04 sentence promising it is the kind of open option that gets more expensive every sprint it is not taken.

**Neutral** — the development stack, the compose file and the staging definition all name PostgreSQL, which is why a natively installed instance on the same machine is a documented failure mode rather than a curiosity ([Installation and Deployment](../../operations/01.%20Installation%20and%20Deployment.md) §9, `KELIR_POSTGRES_PORT`).

## 5. Compliance

The migration suite applies to a PostgreSQL database in CI and the release process requires it to apply cleanly to an empty database and to a copy of the previous release's schema ([release process](../../standards/04.%20Release%20Process.md) §4). There is no portability check, deliberately.

## 6. Revisit When

A deployment Kelir must serve mandates another engine — and then the question is not "add a compatibility layer" but which PostgreSQL-shaped guarantees ([ADR-0022](0022.%20Numbering%20Counters%20Live%20in%20Per-Scope%20Buckets.md)'s upsert, `D-19`'s total index, the row locks in `D-30` and `D-46`) are re-derivable there.
