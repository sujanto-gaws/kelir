# ADR-0005 — An Internal Workflow Engine Instead of BPMN

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-04 (founding) · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** [ADR-0006](0006.%20Metadata-Driven%20Forms%20and%20Lists.md), [ADR-0019](0019.%20A%20Workflow%20Definition%20Is%20Narrowed%20at%20Save%20Time.md), [ADR-0020](0020.%20The%20Workflow%20Owns%20the%20Document%20Status.md), [ADR-0021](0021.%20AllowedBy%20Authorizes%20and%20Does%20Not%20Select.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from [architectures/01](../01.%20Basic%20Framework%20Concept%20and%20Architecture.md) §29 Decision 5. The operative description of the engine is [SDD](../../design/01.%20System%20Design%20Document.md) §8.5 and the definition language is [JWSS](../../schema/JSON%20Workflow%20Schema.md) (standard §9).

The founding concept is documents moving through approvals under a central engine ([concepts/01](../../concepts/01.%20Concept.md)). That engine could have been an existing BPMN product — the mature ones at the time were Java services — or something written for this product.

## 2. Decision

**Kelir runs its own lightweight workflow engine, defined by JWSS, in the backend process.** States, transitions, tasks, assignment rules, guards and actions are JSON; there is no BPMN runtime and no external process.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. A lightweight internal engine** | JSON definitions executed in-process | **Chosen** |
| B. Camunda or Flowable | Full BPMN, mature tooling | Rejected for now — an external Java dependency early; explicitly available later if full BPMN is required |

### A. The internal engine — chosen

Simpler, fits the RAD concept, and avoids an external Java dependency early (architectures/01 §29). Because the engine is the product's own, its definition language could be designed for the thing Kelir actually does: a definition binds to a document type, projects a document status, and names who may take each edge.

### B. Camunda / Flowable

Kept open in the founding record — *"Later can integrate Camunda or Flowable if full BPMN is required."* It buys the BPMN standard, a modeller and an execution semantics nobody has to argue about; it costs a second runtime, a second deployment, and a translation layer between BPMN's vocabulary and this product's documents and permissions.

## 4. Consequences

**Positive** — the engine and the product share one transaction, one permission model and one audit trail: a decision writes the task, the approval, the history row and the document's status together.

**Negative** — every semantic BPMN would have supplied has to be decided here, and each one has been: what a definition may declare and what is refused at save ([ADR-0019](0019.%20A%20Workflow%20Definition%20Is%20Narrowed%20at%20Save%20Time.md)), whether `allowedBy` selects or authorizes ([ADR-0021](0021.%20AllowedBy%20Authorizes%20and%20Does%20Not%20Select.md)), which side owns the document's status ([ADR-0020](0020.%20The%20Workflow%20Owns%20the%20Document%20Status.md)), where a resubmission enters ([ADR-0023](0023.%20Resubmission%20Enters%20Through%20the%20Document%20Submit.md)). Features BPMN gives away — timers, sub-processes, compensation — are absent; system tasks are not built (FR-WF-005, targeted at Sprint 14 by `D-43`), so an `AUTO` transition has had no driver since Sprint 10.

**Neutral** — JWSS is a `Draft Standard` carrying its own revision history, which is what let `requiresComment` be added as a strict widening without a version bump (`D-41`).

## 5. Compliance

`tests/workflow_engine.rs` holds the engine's behaviour; the JWSS meta-schema is compared byte-for-byte against the extracted artifact by a backend test, so the specification and what the product enforces cannot drift.

## 6. Revisit When

A deployment needs BPMN interchange with another system, or the semantics being decided one at a time start contradicting each other rather than composing — the point at which "we are writing a workflow engine" stops being incidental.
