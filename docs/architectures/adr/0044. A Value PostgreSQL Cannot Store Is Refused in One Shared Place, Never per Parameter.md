# ADR-0044 — A Value PostgreSQL Cannot Store Is Refused in One Shared Place, Never per Parameter

**Status:** Adopted · **Last updated:** 2026-09-30

**Decision date:** 2026-09-30, adopted at the merge of [#612](https://github.com/sujanto-gaws/kelir/pull/612) · **Deciders:** Product owner (#601's criterion 10: the fix binds every list route, so it carries an ADR) · **Supersedes:** — · **Superseded by:** — · **Related:** [ADR-0003](0003.%20PostgreSQL%20as%20the%20Only%20Database.md), [ADR-0017](0017.%20Field%20Refusals%20Answer%20422%20with%20the%20S10.3%20Envelope.md), [ADR-0043](0043.%20A%20Test%20Call%20Runs%20in%20the%20Request,%20Resolves%20Only%20env%20Secrets,%20and%20Connects%20Only%20to%20a%20Checked%20Address.md), issues [#601](https://github.com/sujanto-gaws/kelir/issues/601), [#594](https://github.com/sujanto-gaws/kelir/issues/594), [#575](https://github.com/sujanto-gaws/kelir/issues/575), [#610](https://github.com/sujanto-gaws/kelir/issues/610)

## 1. Context

**Two values a Rust type holds are refused by PostgreSQL when they are bound** ([ADR-0003](0003.%20PostgreSQL%20as%20the%20Only%20Database.md)). `text` cannot hold a NUL (0x00): the statement fails with *invalid byte sequence for encoding "UTF8": 0x00*. `timestamptz` starts at 4714 BC, and chrono parses dates back to year −262143. Bound into a statement, either value fails it, and the caller is told `INTERNAL_ERROR` (500) for a mistake in their own request. A NUL reaches any query-string value as `%00`. A date reaches any parameter typed `DateTime<Utc>`.

**Both defects had been fixed one parameter at a time.** [#597](https://github.com/sujanto-gaws/kelir/pull/597) refused a NUL in every list's `search` through `utils::search::parse_search`, and [#595](https://github.com/sujanto-gaws/kelir/pull/595) refused an out-of-range date on `GET /integration/logs`. **`GET /audit` had both defects a sprint later**, because nobody had looked at it: `objectType` and `eventType` answered 500 to `%00`, `from` and `to` answered 500 to `-5000-01-01T00:00:00Z`, and a bound a nanosecond before PostgreSQL's range was accepted and matched as the first instant. `/rad/lists/{id}/rows` did not refuse a NUL in `sort`, `dir` or a filter. A NUL in a uuid, an enum or a closed-vocabulary string was refused, but as `INVALID_TYPE`, `UNKNOWN_VALUE` or `INVALID_VALUE`, depending on which parse failed first.

What already existed, and bounds the choice:

- **Every route that reads a query string reads it through `crate::extract::QueryParams`**: 33 handlers, all of them `get`, and no `axum::extract::Query` anywhere in the crate. `QueryParams` exists because axum's own rejection was not the envelope (#122). It deserializes with `serde_urlencoded` and names a failing parameter as the caller spelled it.
- **A refusal of a field is a 422 `VALIDATION_ERROR`** with one detail per field, each carrying `path`, `rule`, `code` and `message` ([ADR-0017](0017.%20Field%20Refusals%20Answer%20422%20with%20the%20S10.3%20Envelope.md)).
- **Some query types collect keys they do not declare.** `RowQuery` flattens a list's filters into a map, so the names a query carries are not all known from the type.
- **Two services take a date range**: `audit::service::search_audit` and `integration::domain::log::validate_query`.
- **The OpenAPI document is generated and held equal to the routes served** (`router::tests::every_annotated_route_reaches_the_document`), so it can enumerate the routes without a hand-kept list.

[#601](https://github.com/sujanto-gaws/kelir/issues/601) asked for a 422 on every list route, seen red against `/audit` first, with [#594](https://github.com/sujanto-gaws/kelir/issues/594) (the date half) folded in. Its criterion 10 requires this record if the fix binds every list route.

## 2. Decision

**Kelir refuses a value PostgreSQL cannot store before any statement binds it, as a 422 `VALIDATION_ERROR` naming the parameter, in one shared place per kind of value, never parameter by parameter.**

- **A NUL is refused in the extractor.** `QueryParams::from_request_parts` calls `refuse_nul` on the raw query before it deserializes anything. Every parameter whose decoded value holds a NUL is named once, with `path` the key as sent, `rule` `pattern` and `code` `INVALID_CHARACTER`. That covers every value a query string carries: declared, flattened into a map, or ignored by the type. It binds all 33 routes that read a query string, and every route written later that reads one through `QueryParams`, which the coding standard requires ([§2.6](../../standards/01.%20Coding%20Standard.md)).
- **A date bound is refused by the service that knows it is a date.** `utils::storable::refuse_out_of_range(&[(field, value)])` names **every** bound outside PostgreSQL's `timestamptz` range, with `rule` `range` and `code` `OUT_OF_RANGE`, compared at nanosecond precision. Every service that takes a date range calls it before its query: today `search_audit` and `validate_query`.
- **The shared pieces live in `utils::storable`**: `nul_refusal`, which builds the NUL's detail wherever it is found, and the codes `INVALID_CHARACTER` and `OUT_OF_RANGE`. `parse_search` builds its NUL detail through `nul_refusal`, and stays as the rule for a search term wherever the term comes from. Over HTTP its NUL branch is now a second line of defence, commented as unexercised.

**Out of scope, and not covered by this decision:**

- **A string path parameter.** `PathParam<String>` values, `list_key` on `GET /rad/lists/by-key/{list_key}` among them, reach a bind with no NUL check.
- **A string in a JSON body.** `JsonBody` strings reach a bind with no NUL check. That is the class of [#575](https://github.com/sujanto-gaws/kelir/issues/575) and [#610](https://github.com/sujanto-gaws/kelir/issues/610).

Neither is covered here. Each needs its own shared place (§6).

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. The NUL in `QueryParams`, the date in a shared service check** | One refusal per kind of value, each where the knowledge it needs lives | **Chosen** |
| B. `parse_search` per parameter | Each route guards the parameters it knows are strings | Rejected — it is how `/audit` was missed |
| C. Strip the NUL | Remove 0x00 and answer the search | Rejected — it answers a question nobody asked |
| D. A check per repository before binding | Each repository refuses what it is about to bind | Rejected — per statement is per parameter again, and a repository cannot name the parameter as sent |
| E. A tower middleware on the raw URI | Refuse `%00` before routing | Rejected — it knows no parameter to name, and refuses routes that read no query |
| F. The date bound in the extractor | `QueryParams` refuses any value that parses as an out-of-range instant | Rejected — only the type knows which strings are instants |

### A. The NUL in `QueryParams`, the date in a shared service check — chosen

**A NUL is wrong in every string of every request, whatever the parameter means**, so the extractor can refuse it without knowing the type it is filling. Every query string already passes through `QueryParams`, so the refusal reaches every route by construction, including values the type never declares. Running before deserialization gives a NUL one answer, `INVALID_CHARACTER`, whatever parse would have failed first. **A date is a date only once the type says so**: `from=-5000-01-01` is a valid string. So the bound lives in one function, and the code that knows which fields are instants calls it. **What it does not solve:** a new date-range service that forgets the call. The walk in §5 catches that for any documented `date-time` parameter.

### B. `parse_search` per parameter

This was the shape before #601: each list read its search term through `parse_search`, which refuses the NUL, and #595 added the date check to one route. Each fix was correct, and each covered the parameters its author looked at. `/audit`'s `objectType` and `eventType` are strings that are not called `search`, so nobody looked at them, and they answered 500. A rule applied parameter by parameter is only as complete as the author's list.

### C. Strip the NUL

A search for `a\0b` would become a search for `ab`, and the list would answer a question the caller did not ask. No row can contain a NUL, so a refusal loses no match. `parse_search` already refused rather than stripped for this reason, and a uuid or an enum with the NUL removed would be a different value, silently.

### D. A check per repository before binding

It would sit next to the bind, which is where the failure happens. It needs one check per statement, which is per parameter with a different name. It also runs after the query struct has been mapped to arguments, so it knows the column and not the parameter the caller sent, and a 422 naming a column is not one a caller can correct.

### E. A tower middleware on the raw URI

One layer would see every request, including routes that are not lists. It works before the query is split into parameters, so it cannot name the parameter without splitting it again, and it would refuse `%00` on a route that reads no query at all. `QueryParams` already splits the query, knows it is a query, and runs only where one is read.

### F. The date bound in the extractor

The extractor sees strings. To refuse an out-of-range instant it would have to guess which strings are instants, by trying to parse each value as one. That refuses `name=-5000-01-01T00:00:00Z` on a route where it is a name, and still misses a date format the type parses and the guess does not.

## 4. Consequences

**Positive**

- A NUL in any query value answers the same 422 on every route, and a route written tomorrow gets it without a line of its own.
- `/audit` answers 422, not 500, to a NUL and to an out-of-range date, and refuses a bound a nanosecond before PostgreSQL's range.
- A caller whose `from` and `to` are both out of range is told both at once.
- The walk found two query types, `RowQuery` and `ActionQuery`, that the OpenAPI document listed as required path parameters, which a generated client would have followed. Both are now documented as query parameters.

**Negative**

- **A NUL in a uuid, an enum or a closed-vocabulary parameter now answers `INVALID_CHARACTER`**, where it answered `INVALID_TYPE`, `UNKNOWN_VALUE` or `INVALID_VALUE`. A client matching on the old codes sees a new one.
- **A NUL in a parameter the route ignores is refused.** `?somethingElse=a%00b` was accepted and is now a 422, although nothing would have bound it.
- **A NUL in a query key is not refused.** A key is matched against names and never bound, so the extractor passes it, and a type that one day binds a map key would need its own check.
- **The date half is a call a service must remember.** Nothing in the type system makes a service that takes a date range call `refuse_out_of_range`. The walk catches the omission only for a parameter the OpenAPI document lists as `date-time`.
- **Two places a string reaches a bind are not covered**: a `PathParam<String>` value and a `JsonBody` string (§2).

**Neutral**

- A new module, `utils::storable`, and two detail codes, `INVALID_CHARACTER` and `OUT_OF_RANGE`. `utils::search::NUL_IN_SEARCH` becomes an alias for `INVALID_CHARACTER`.
- `parse_search`'s NUL branch is a second line of defence over HTTP, commented as unexercised ([coding standard](../../standards/01.%20Coding%20Standard.md) §2.5).

## 5. Compliance

**`kelir-backend/tests/list_route_refusals.rs`** holds the decision without naming a route or a parameter. It reads every `get` with a query parameter from `ApiDoc::openapi()`, classifies each parameter by its schema, and sends each class what PostgreSQL cannot store. It asserts that:

- a NUL in every string, enum, uuid and map parameter is a 422 `INVALID_CHARACTER` on that parameter (`%00` and `a%00b` on a string, `%00` on an enum or uuid, `a%00b` under one key of its own on a map), and on a string `a%01b` is not refused;
- every string parameter also receives `-5000-01-01T00:00:00Z` and must not answer 500, so a date the document misdescribes as a string is still sent a date PostgreSQL cannot store;
- a `date-time` parameter at `-5000-01-01T00:00:00Z` and at a nanosecond before PostgreSQL's first instant is a 422 `OUT_OF_RANGE` with `rule` `range`, and the first instant itself is accepted;
- when an operation has two date bounds and both are out of range, both are named;
- no cell answers 500, and, last, every operation with an empty query is served: a 2xx, a 404 for an unresolved capture, or a 422 naming only a parameter the document marks `required`.

**The guard stops the walk from walking nothing.** It counts `QueryParams<` in every `modules/**/handlers.rs` and requires the walked operations to number the same, 33 of 33. A handler that reads a query string and documents no parameter is one the walk cannot see, and the count reddens. It also requires at least one parameter of every class, the map included. Its first run, before the fix, found 31 operations against 33 sites: `RowQuery` and `ActionQuery`.

**Seen red** ([coding standard](../../standards/01.%20Coding%20Standard.md) §2.9), 2026-09-30: the file's module header carries the run against `main` before the fix, 57 of 291 cells, and seven mutations, each with what it reddened. `refuse_nul` removed reddens 52 cells. `refuse_out_of_range` removed from either service reddens that route's five date cells. The `test-engineer` gate added the string's date cell, the stricter positive control and the map in the guard, each against a mutation the walk had passed. The same header records those three.

`extract.rs`'s unit tests hold the extractor alone: a NUL named as sent, refused before parsing, refused in an ignored parameter, each parameter named once, and a NUL in a key passed. `storable.rs`'s unit tests hold the bounds against PostgreSQL's own constants.

**What the walk cannot see, and a reviewer checks:**

- **A handler outside a `handlers.rs`, or a query read another way.** The guard counts one spelling in one file name. A route that reads a query string reads it through `QueryParams` (coding standard §2.6).
- **A new service taking a date range calls `refuse_out_of_range`** before its query, and its parameters are typed `DateTime<Utc>` so the document lists them as `date-time`.

## 6. Revisit When

- **A NUL in a path parameter or a JSON body string reaches a bind as a 500**, as [#575](https://github.com/sujanto-gaws/kelir/issues/575) and [#610](https://github.com/sujanto-gaws/kelir/issues/610) describe for bodies. The same rule then needs its shared place in `PathParam` or `JsonBody`, and this record is extended by a later one.
- **A query type binds a map key**, not only a value. The extractor's pass on a NUL in a key then stops being safe.
- **A third kind of unstorable value is found**, such as a number outside a column's range that the Rust type holds. It joins `utils::storable`, or the invariant is restated.
