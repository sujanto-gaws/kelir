# ADR-0031 — An External Reference Is Not an Attachment Row

**Status:** Draft · **Last updated:** 2026-09-02

**Decision date:** — · **Deciders:** Sprint 13 item 5's author, at construction — **author-verified** ([sprint plan](../../../projects/planning/01.%20Sprint%20Plan.md) §2), so this record stays `Draft` until a second reader has it · **Supersedes:** — · **Superseded by:** — · **Related:** `D-53`, [ADR-0032](0032.%20A%20Soft-Deleted%20Attachment%20Keeps%20Its%20Object.md), FR-ATT-010, issue [#254](https://github.com/sujanto-gaws/kelir/issues/254)

## 1. Context

**Written when the decision was taken** (standard §9).

[SRS](../../requirements/srs.md) §4.10 FR-ATT-010 says *the system shall support external document references*, `Should`. Nothing in the design set said what one is: [concepts/02](../../concepts/02.%20Handling%20Attachments%20Comments%20and%20Activity%20Log.md) §3.1 sketches the attachment table and never mentions links, and the [Database Schema](../../design/02.%20Database%20Schema.md) §8 had no table for them.

What did exist was `attachments`, and it is close enough to be tempting. Its row already carries a document, a category, a description, an uploader and a soft delete. The difference is five columns: `file_size`, `checksum`, `mime_type` and `storage_reference` are **`NOT NULL`**, and `virus_scan_status` is `NOT NULL DEFAULT 'PENDING'` with a `CHECK` over four values, every one of which is a claim about a scan that happened or did not.

[#254](https://github.com/sujanto-gaws/kelir/issues/254) makes both of those load-bearing. **AC4** asks that a reference be *visibly not a file* everywhere attachments are listed — no size, no scan status, no download. **AC5** asks that it *never be scanned and never read `CLEAN`*, because [#246](https://github.com/sujanto-gaws/kelir/issues/246) spent an item making `CLEAN` mean *this was scanned and passed*.

And one constraint that is not about design taste: `v0.5.0`'s binary is still running during a rolling deploy, and it reads `attachments.file_size` and `virus_scan_status` through `sqlx::query!` into **non-null Rust types**.

## 2. Decision

**Kelir records an external reference in its own table, `document_external_references`, and never as a row in `attachments`.** It has a label, a URL, an optional description and the same category vocabulary; it has no size, no checksum, no MIME type, no storage reference and **no scan status**. It is served by its own collection under the document (`/api/v1/documents/{id}/references`) and its own type (`ExternalReference`). The screen shows both in one list and marks which is which; the API does not merge them.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. Its own table and its own collection** | A link is a different thing | **Chosen** |
| B. A row in `attachments` with sentinel values | No migration beyond a column | Rejected — the sentinels would have to lie, and one of them would lie about a scan |
| C. A row in `attachments` with the file columns made nullable | Honest nulls, one list | Rejected — breaks `v0.5.0`'s list at run time, and pushes *is this a file* into every reader |
| D. A `kind` discriminator on `attachments` | Explicit, one table | Rejected — C's nulls with a flag on top; the flag is the type this decision gives it instead |

### A. Its own table — chosen

**The type is the enforcement.** AC4 and AC5 are satisfied by there being no field to get wrong: `ExternalReference` has no `virusScanStatus`, so nothing can render a scan badge for a link or read `CLEAN` off one, in this client or the next. A convention that says *do not show the size for references* is a convention somebody forgets in the second screen.

**The scan worker cannot see it either**, and that is the same property from the other side: `repository::pending_scans` selects from `attachments`, so a reference is not merely never scanned — it is not in the set anything scans.

**What it costs is named in §4**: two collections, and a screen that fetches both.

### B. Sentinels in `attachments`

`file_size = 0`, `checksum = ''`, `storage_reference = ''` and — the one that settles it — a `virus_scan_status` of something. `CLEAN` is a claim that a scan passed, which #246 forbids. `PENDING` says *being checked*, which is false for ever. `FAILED` says *could not be checked*, which reads as a defect. There is no value that is true, which is what tells you the row does not belong in the table.

### C. Nullable file columns

Honest about absence, and it breaks the previous release. `v0.5.0` selects `file_size` and `virus_scan_status` into non-null types; a null in either fails **its list query at run time**, for every caller looking at a document that has a reference — not at deploy, not in a migration check, but in an error somebody reports. The [release process](../../standards/04.%20Release%20Process.md) §6 N−1 rule exists for exactly this, and a new table is the one shape that cannot reach it.

It also spreads: every read of `attachments` would gain *and is this actually a file*, and the first place somebody forgets it is the place it matters.

### D. A discriminator column

C with a flag, and the flag does not fix C: the columns are still nullable, the previous release still breaks, and every query still branches. What a discriminator buys is one collection — which §4 grants is a real loss under A, and not worth the run-time break.

## 4. Consequences

**Positive** — AC4 and AC5 hold by construction rather than by review. The migration is additive: one new table, no `ALTER` to `attachments`, and the previous release names the table in no statement. A reference gets its own permission (`attachment:reference`), so a deployment can allow linking without allowing uploads — a distinction B and C could not express.

**Negative, accepted** — **two collections and two calls.** A screen that shows files and links together fetches both and merges them, which is a page-size question the moment a document has many of each: the two lists paginate independently, and *the first page of each* is not *the first page of both*. `AttachmentsTab.vue` loads page one of each today and says so. If a merged, paginated surface is ever needed, it is a third endpoint over both tables rather than a change to this decision.

**Negative** — a category is now referenced from two tables, so a category delete has two places to check. `attachment_categories` has no delete surface yet; when it gets one, this is a thing it must know.

**Neutral** — `EXTERNAL_REFERENCE` joins the audit trail's object-type vocabulary, and `Reference.Added` / `Reference.Deleted` join the activity vocabulary. Both are new names rather than reused ones, deliberately.

## 5. Compliance

`a_reference_records_a_link_and_carries_none_of_a_files_fields` asserts the payload has no `fileSize`, `checksum`, `mimeType` or `virusScanStatus`; `a_reference_is_not_an_attachment_and_is_never_scanned` asserts a recorded link puts no row in `attachments` — the table the scanner reads. On the screen, `shows a link as a link rather than as a file` holds the badge, the absent scan status and the absent download.

A reviewer adding a field to `ExternalReference` asks one question: does this field exist because a *file* has it? If so, it belongs on `Attachment`.

## 6. Revisit When

A merged, paginated collection over both tables is needed — a document with dozens of each, or an export that has to interleave them; or `attachment_categories` gains a delete surface, which is the one place these two tables are coupled.
