# ADR-0050 — A NUL in a Path or a Body, and a Body Date PostgreSQL Cannot Store, Are Refused Where Each Is Read

## 1. Context

**Written when the decision was taken, before its build**, from row 13's criteria and the code on `main` at `d767b48`. The two sign-in 500s below were seen by the build on that commit, and are marked as such.

**[ADR-0044](0044.%20A%20Value%20PostgreSQL%20Cannot%20Store%20Is%20Refused%20in%20One%20Shared%20Place,%20Never%20per%20Parameter.md) refused a value PostgreSQL cannot store in one shared place per kind of value, and it covered the query string only.** `QueryParams` refuses a NUL in any query value, and `utils::storable::refuse_out_of_range` refuses a date bound outside `timestamptz`'s range in the two services that take one. Its §2 left two places out by name: a string path parameter, and a string in a JSON body. Its §6 named the trigger that reopens them, *a NUL in a path parameter or a JSON body string reaches a bind as a 500*, and where the rule would then go: `PathParam` or `JsonBody`, in a later record.

**That trigger fired.** [#657](https://github.com/sujanto-gaws/kelir/issues/657): `GET /rad/lists/by-key/%00` answers 500, because `list_key` reaches a bind through `renderable_list`. [#668](https://github.com/sujanto-gaws/kelir/issues/668) names three more of the same class:
- **P8**: `PUT /master-data/parties/{id}/roles/{roleTypeId}` binds the role type before it looks the party up (`service/role.rs`), so a NUL there reaches a bind whether or not the party exists.
- **P7**: a NUL in a JSON body string, such as `"roleCode":"R21-P7\u0000"` on `POST /identity/roles`, reaches a bind.
- **P6**: a date in a body that PostgreSQL cannot store, such as a credential's `"validFrom":"-5000-01-01"`, reaches a bind. ADR-0044's date half had its NUL half's shape: query only.

What existed at `d767b48`, and bounds the choice:

- **`PathParam` wraps `axum::extract::Path::<T>`**, so it parses before anything can look at a capture. It has 100 sites in the 13 `modules/**/handlers.rs` files. **Four handlers take a string capture**, and the other 96 take a `Uuid` or a `(Uuid, Uuid)`:

  | Route | Reaches a bind |
  |---|---|
  | `GET /rad/lists/by-key/{list_key}` | Yes, through `renderable_list`: #657 |
  | `GET /rad/lookups/{source}/options` | No. `LookupSource::from_key` answers 404 first |
  | `PUT /master-data/parties/{id}/roles/{roleTypeId}` | Yes, before the party is read: P8 |
  | `DELETE` on the same path | Likely, through `remove_role` |

  A NUL in a uuid capture is a 400, the parse's failure, which #122 kept: *a path segment that will not parse stays a 400*.
- **The two party-role routes carry no `params(...)` in their annotations.** The OpenAPI document does not say their captures are strings, so nothing that reads the document can tell them from a uuid.
- **`JsonBody` deserializes `T` from the bytes** through `serde_path_to_error`, and names a failing field at its path as sent. It has 52 sites, **six of them in `auth/handlers.rs`**, which no token guards. A raw NUL byte is invalid JSON and already a 400. The six-byte escape `\u0000` is valid JSON, deserializes into a `String` holding `'\0'`, and nothing refuses it.
- **Two of those six routes answer 500 to a caller with no token.** The build saw it on `main` at `d767b48`: `POST /api/v1/auth/login` and `POST /api/v1/auth/forgot-password`, each with `"username":"admin.kelir\u0000"`, answered 500, *invalid byte sequence for encoding "UTF8": 0x00*. The other auth fields did not. **This is the strongest reason the body refusal is built in this row** rather than tracked: anyone who can reach the sign-in route can cause that 500.
- **Some body fields are free-form.** A form or a list definition is a `serde_json::Value`, and its keys are stored, so a body's keys can reach a bind as well as its values.
- **Body dates PostgreSQL narrows: 22 fields in 12 request structs, on 8 routes.** They are a credential's validity on create and update (the update's are `Option<Option<NaiveDate>>`, through `utils::serde::present_or_absent`), a document type's workflow binding's validity, the parties' dates, a party role's dates and its customer and employee profiles' dates, and a delegation's `startsAt` and `endsAt`. They are `NaiveDate`, `DateTime<Utc>`, or an `Option` of either.
- **The lower bound, checked on PostgreSQL 17 by the main session on 2026-10-30.** `'4714-11-24 BC'` is the lowest value for both `date` and `timestamptz`, which is `-4713-11-24` in chrono, and `'4714-11-23 BC'` is out of range for both. **Only the lower bound can fire**: chrono stops at year 262143 (`storable.rs`), below both types' upper bounds. `within_postgres_range` takes a `DateTime<Utc>` only.
- **`Authenticated` is the first extractor of every protected handler** ([ADR-0045](0045.%20Every%20Authenticated%20Request%20Reads%20That%20Its%20Tenant%20and%20User%20Are%20Not%20Deleted,%20and%20a%20Token%20Has%20No%20Leeway.md)), and `deleted_caller_campaign.rs` pins that. The permission is checked in the service, after every extractor (coding standard §2.6).
- **A refusal of a field is a 422 `VALIDATION_ERROR`**, one detail per field, each with `path`, `rule`, `code` and `message` ([ADR-0017](0017.%20Field%20Refusals%20Answer%20422%20with%20the%20S10.3%20Envelope.md)). `utils::storable` already holds `nul_refusal` and the codes `INVALID_CHARACTER` and `OUT_OF_RANGE`.

**Why this is a new record, and not an amendment of ADR-0044.** #657's comment said this change would amend ADR-0044. It does not. ADR-0044 decided that these two places were out of its scope, and bringing them in changes what it decided, not a realization detail. By [standards/06](../../standards/06.%20Architecture%20Decision%20Records.md) §6 that is a new record, superseding the part it replaces, as [ADR-0047](0047.%20A%20Tenant%20Resolves%20Only%20env%20Secrets%20Named%20for%20It,%20and%20Four%20Cloud%20Metadata%20Addresses%20Are%20Always%20Refused.md) did for ADR-0043. **ADR-0044's decision itself is not reversed**: refusal in one shared place, never per parameter, stands, and this record applies it to two more places and to the dates a body carries. No force moved. ADR-0044 left the two places for later, and named the trigger that has now fired.

## 2. Decision

**Kelir refuses a NUL in a path capture and in a JSON body, and a date in a request body that PostgreSQL cannot store, each in the one shared place that reads it, before any statement binds it, as a 422 `VALIDATION_ERROR` naming the field as the caller sent it.** ADR-0044's rule, one shared place per kind of value and never per parameter, now covers every place a request carries a string or a date to a bind.

- **A path capture is checked in `PathParam::from_request_parts`, before `Path::<T>`.** It reads `RawPathParams`, the router's decoded captures, and refuses every capture whose value holds `'\0'` with `storable::nul_refusal(name)`. The detail's `path` is the capture's name as the route declares it, such as `roleTypeId`, with `rule` `pattern` and `code` `INVALID_CHARACTER`.
  - It follows `refuse_nul`'s order, check then parse, so a NUL in a uuid capture is `INVALID_CHARACTER` and not the parse's 400.
  - A tuple capture names only the member that holds the NUL.
  - It covers every route that takes a capture, string or uuid, whether or not its annotation lists the capture.
  - It is not a middleware: ADR-0044 rejected that as its option E, for the reasons §3 B repeats.
- **A JSON body is checked in `JsonBody::from_request`, before `T` is deserialized.** It scans the body's bytes for the escape `\u0000`.
  - **Only when the escape appears** does it parse the body to a `serde_json::Value` and walk it (`refuse_nul_in_body`, through `nul_paths`). Each string value and each object key holding a NUL is refused at its path as sent, such as `items[0].name`, written with `.` and `[i]` as `rejection` names a failing field.
  - **The `Value` is used only to find NULs. `T` is always deserialized from the bytes**, on both paths, exactly as before. The scan is a fast path only: a false hit, an escaped backslash followed by `u0000` (`"\\u0000"`), takes the slower path, finds no NUL, and is read exactly as before. A unit test holds that the scan and the walk agree.
  - **A body carrying the escape that a `Value` cannot read is a 400**, *Request body is not valid JSON*, before `T` is tried (added 2026-10-30, row 13's gate). A lone surrogate, a number past `f64` or nesting past 128 fails the `Value`, and a type that ignores unknown fields would skip such a value and read a NUL elsewhere in the body. Every `JsonBody` type denies unknown fields today, so no route answered differently; this keeps it so for a type that does not.
  - A raw NUL byte stays what it is, invalid JSON and a 400.
- **A date field of a request body is read through a `deserialize_with` helper in `utils::storable`**: one per date shape:

  | Shape | Helper |
  |---|---|
  | `NaiveDate` | `date` |
  | `Option<NaiveDate>` | `option_date` |
  | `Option<Option<NaiveDate>>` | `present_or_absent_date`, composed with `utils::serde::present_or_absent` |
  | `DateTime<Utc>` | `instant` |
  | `Option<DateTime<Utc>>` | `option_instant` |

  - Each deserializes the value, then checks it against PostgreSQL's lower bound: `within_postgres_range` for an instant, and a new `NaiveDate` sibling for a date. `-4713-11-24` is accepted and the day before is refused.
  - Out of range, the helper fails with `serde::de::Error::custom` carrying a sentinel. `extract.rs`'s `detail` maps the sentinel to `rule` `range` and `code` `OUT_OF_RANGE`, at the field's path, nested where it is nested (`person.birthDate`).
  - **"Never per parameter" is met by one implementation and a guard.** Every one of the 22 fields carries a helper, and a source-scan guard, `every_request_date_field_reads_through_a_storable_helper`, refuses a request date field that lacks its shape's helper, or has a date shape outside the five (§5).

**Scope.** It covers every `PathParam` capture, every `JsonBody` body, and every `NaiveDate` or `DateTime<Utc>` field of a `Deserialize` request struct, with an `Option` of either. ADR-0044's query half, `QueryParams` and `refuse_out_of_range`, is unchanged. **It leaves open**: a range for any other column type; string length bounds ([#575](https://github.com/sujanto-gaws/kelir/issues/575) and [#610](https://github.com/sujanto-gaws/kelir/issues/610), closed); a body that is not valid UTF-8, a multipart filename and a header; a NUL in a query key, which ADR-0044 §4 still passes; and `parse_search`.

## 3. Options Considered

Each of the three places had its own options. The chosen shape is one option across all three, because each is the same rule: refuse where the value is read.

| Option | Summary | Verdict |
|---|---|---|
| **A. Each refusal where the value is read** | `PathParam` reads `RawPathParams` first; `JsonBody` walks a `Value` when the escape appears; `storable` helpers on every body date | **Chosen** |
| B. Path: a tower middleware on the raw path | Refuse `%00` in the URI's path before routing | Rejected — ADR-0044's option E: it knows no capture to name, and refuses a `%00` that names no capture |
| C. Path: a check in each of the four string-capture handlers | Fix #657 and P8 where they bind | Rejected — per parameter: ADR-0044's option B, and how `/audit` was missed |
| D. Path: a check after `Path::<T>` parses | Refuse a NUL in what the parse produced | Rejected — a uuid's parse fails first, so a NUL is a 400 on 96 routes and a 422 on four |
| E. Body: always parse to a `Value` and walk it | No byte scan; every body walked | Rejected — every body on 52 routes pays a second parse, for a value ordinary traffic never carries |
| F. Body: a runtime schema walk | Walk the request type's schema to find its string fields | Rejected — needs `T: ToSchema` on `JsonBody`, and cannot see inside a free-form `Value` or a key |
| G. Dates: a newtype | A `StorableDate` type in place of `NaiveDate` and `DateTime<Utc>` | Rejected — 22 fields ripple into every bind and every OpenAPI `value_type` |
| H. Dates: a check in each service | Each service calls `refuse_out_of_range` on its body's dates, as ADR-0044's date half does | Rejected — eight routes in five modules must each remember, and nested paths are named by hand |

### A. Each refusal where the value is read — chosen

**Every request reads its captures through `PathParam` and its body through `JsonBody`**, so a refusal in either reaches every route by construction, the routes written later included. That is ADR-0044's argument for `QueryParams`, one place over each time.

- **The capture check reads `RawPathParams` before it parses**, so a NUL has one answer, `INVALID_CHARACTER`, whatever the capture's type. That is ADR-0044's query rule, which already answers `INVALID_CHARACTER` for a query uuid. It names the capture as the route declares it, the name a caller reads in the path template. It does not need the OpenAPI document to say which captures are strings, which two of the four routes' annotations do not.
- **The body check costs nothing on an ordinary body.** A body without the escape is never parsed twice. The walk sees every string and every key, including those in a free-form `Value`, and names each where it sits. It runs before `T` is deserialized, so a NUL is reported without the body having to be otherwise valid.
- **The date helpers put the check where serde already names the path.** A failing helper is a deserialization error like any other, so `rejection` names `person.birthDate` without a line of path-building, and every route that reads the struct gets the check.

**What it does not solve.** The date half is still one attribute per field, which is per field by construction even with one implementation. The guard is what turns a forgotten attribute into a red test, and it reads source, so a struct outside its reach is the reviewer's (§5).

### B. Path: a tower middleware on the raw path

One layer would see every request. It would see the path before the router splits it, so it would know no capture to name, and it would refuse a `%00` in a segment that names no capture, which is a 404 today. ADR-0044 rejected the same shape as its option E. `PathParam` already holds the router's captures, by name.

### C. Path: a check in each of the four string-capture handlers

It is the smallest fix: #657 and P8 are two handlers, and `remove_role` and the lookups are two more. It is per parameter, ADR-0044's option B. Each fix would be correct and would cover the captures its author looked at, and a fifth string capture written next sprint would answer 500 until someone found it. A NUL in a uuid capture would also keep answering 400, a different answer for the same mistake.

### D. Path: a check after `Path::<T>` parses

It needs no new reader: refuse a NUL in what the parse produced. For a uuid nothing is produced, because the parse fails first, so a NUL is a 400 on 96 routes and a 422 on four. For a generic `T`, the extractor has no string to look at without serializing the value back. The `test-engineer` gate names this shape as a mutation to kill: *the check run only after a successful `Path::<T>` parse, which leaves the uuid cells at 400*.

### E. Body: always parse to a `Value` and walk it

It is simpler than A by one branch, and has no fast path for a test to hold equal to the walk. It costs a second parse and a tree on every body of 52 routes, to find a value that ordinary traffic never carries. Its walk would have A's blind spot on every body rather than on the escape's path only: **a `Value` keeps a repeated key's last copy**, so a NUL in an overwritten copy is not named (§4).

### F. Body: a runtime schema walk

The request type's OpenAPI schema says which fields are strings, so the walk could visit only those. `JsonBody` would need `T: ToSchema`, a bound every request type would carry for this check alone. A free-form `Value` field, such as a form or list definition, has no schema below its top, so the walk could not see a NUL inside one, and a schema says nothing about keys. It would also classify from the document, which the path's two unannotated routes show can be incomplete.

### G. Dates: a newtype

A `StorableDate` and a `StorableInstant` would make the bound a property of the type, and no field could forget it. Each of the 22 fields would change type, so every service that reads one, every bind and every OpenAPI `value_type` would change with it, in five modules, for a check that runs once at the edge. The helpers give the same check with the field's type unchanged, and the guard closes what the type would have closed.

### H. Dates: a check in each service

It is ADR-0044's date half applied to bodies: each service calls `refuse_out_of_range` before its write. **It would name every out-of-range date at once**, which A does not (§4). It is a call each of eight routes in five modules must remember, which ADR-0044 §4 names as its own date half's weakness, and a nested field's path, `person.birthDate`, would be written by hand in each service. The body's dates are typed, so the deserializer can check them, which it could not for a query string.

## 4. Consequences

**Positive**
- **#657, P8, P7 and P6 answer 422 naming the field, not 500.** P8 does so for a party that does not exist, because the capture is refused before the service runs.
- **A NUL has one answer wherever a request carries it**, query, path or body: `INVALID_CHARACTER`, at the name the caller used.
- **Every route with a capture and every route with a JSON body is covered by construction**, including the six sign-in and token routes no token guards, two of which answered 500 to a NUL in `username`, and every route written later that reads through the two extractors.
- **A body date is named where it sits**, nested paths included, and `-4713-11-24` itself is accepted.

**Negative**
- **A NUL in a uuid capture answers 422 `INVALID_CHARACTER` where it answered 400**, on about 96 routes, as ADR-0044 §4 did for query uuids. A client matching on 400 sees a new status.
- **`/rad/lookups/%00/options` answers 422 where it answered 404.** An unknown source with no NUL is still a 404.
- **A 422 can now come before a 403.** `PathParam` and `JsonBody` run before the service checks the permission, so a caller without it who sends a NUL is told 422, as with a query string since ADR-0044. The refusal is about the request's own bytes and says nothing about the data. `Authenticated` still runs first, so a caller with no token is still a 401.
- **A NUL in a value that a later duplicate key overwrites is not named.** The walk reads a `Value`, which keeps only a repeated key's last copy. That overwritten value never reaches `T` either, because `T` is read from the bytes, where a repeated field is refused or replaced by its later copy, so it reaches no bind. The caller is not told about it.
- **A body reports its first out-of-range date only**, because serde stops at the first error. A query names every bound (ADR-0044 §2). A caller with two bad dates in one body corrects them one at a time.
- **A body key holding a NUL is refused, where a query key is not** (ADR-0044 §4). A body's free-form fields store their keys, and a query's keys are only matched against names. So two rules for a key are now in force, each with its reason.
- **The date half is one attribute per field**, held by a guard that reads source. A date shape outside the five fails the guard, but a request struct the guard cannot see, or a date type it does not look for, such as `NaiveDateTime`, is the reviewer's.
- **A body carrying the escape is parsed twice**, both times from the bytes: once to a `Value` to find NULs, once into `T`.

**Neutral**
- **No new detail code.** `INVALID_CHARACTER` and `OUT_OF_RANGE` are ADR-0044's. `utils::storable` gains a `NaiveDate` bound and the date helpers, and `extract.rs`'s `detail` gains the sentinel's mapping.
- **The four string-capture routes' `responses(...)` gain 422.** The 96 uuid routes' annotations do not, and one sentence in SDD §12.3 covers them.
- `parse_search`'s NUL branch stays a second line of defence (ADR-0044 §2).

## 5. Compliance

**`kelir-backend/tests/path_param_refusals.rs` holds the decision without naming a route or a field.** It reads `ApiDoc::openapi()`, as `list_route_refusals.rs` does.

- **The path walk**, `a_nul_in_any_path_capture_is_refused_on_every_route`. It takes every operation with a `{capture}`, any method, modelled on `deleted_caller_campaign.rs`'s `authenticated_operations()`. As the administrator, it sends `%00` and `a%00b` in every capture. Each must answer 422 `VALIDATION_ERROR` with a detail whose `path` is the capture's name, `rule` `pattern` and `code` `INVALID_CHARACTER`, and never 500. **No capture is classified from the document**, because two of the four string captures are not in it.
- **Its guard.** The walked operations must account for every `PathParam<` site in `modules/**/handlers.rs`, 100 at `d767b48`, and at least one capture must not be a uuid. A handler that takes a capture outside `PathParam` turns it red. The build reports the walk covering 100 of 100 sites, 113 captures.
- **The body walk**, `a_nul_in_any_json_body_string_is_refused_on_every_route`. It takes every operation with a JSON `requestBody`, the six auth routes included, and sends `{"walkedField":"a\u0000b"}` and `{"a":[{"b":"\u0000"}]}`. They must answer 422 `INVALID_CHARACTER` at `walkedField` and at `a[0].b`. The refusal runs before the body's shape is checked, so no valid body is needed. `\u0001` is not refused as a NUL.
- **Its guard.** The walked operations must equal the `JsonBody<` sites, 52 at `d767b48`, less any multipart route. The build reports the walk covering 52 of 52.
- **The named tests.** P8 runs against a real party with a valid body, because an empty body is refused by `JsonBody` before the service binds anything, a false green. The same `PUT` against a party that does not exist is 422 too. P7 is `POST /api/v1/identity/roles` with `"roleCode":"R21-P7\u0000"`, and P6 is a credential with `"validFrom":"-5000-01-01"`.
- **The date cells**, `every_body_date_is_refused_below_postgresqls_range_and_accepted_at_it`. Each of the 8 date routes has a cell below the bound and a cell at exactly `-4713-11-24`, which is accepted. The update credential's `null`, which clears, is one of them.
- **The date source guard**, `every_request_date_field_reads_through_a_storable_helper`, in the same file. A `Deserialize` request struct with a date field whose shape's helper (§2's table) is missing, or whose date shape is not one of the five, turns it red. It excludes `IntoParams` structs, which are query types and keep ADR-0044's check. It is seen red with one attribute removed.
- **Unit tests.** `extract.rs`: a path refusal names the capture, runs before deserializing, names only the tuple member that holds the NUL, and refuses a NUL in a uuid capture as `INVALID_CHARACTER`; the byte scan and the walk agree. `storable.rs`: the `NaiveDate` bound accepts the exact day and refuses the day before, and the sentinel round-trips to `OUT_OF_RANGE`.
- **Unchanged.** `list_route_refusals.rs`, and `deleted_caller_campaign.rs`, which pins `Authenticated` as the first extractor, pass unmodified.

**Seen red** ([coding standard](../../standards/01.%20Coding%20Standard.md) §2.9): the new file's header records its run against `main` at `d767b48`, as `list_route_refusals.rs`'s does, with the 500s reported apart from the wrong-code cells; `/rad/lists/by-key/%00` must be among the 500s. The `test-engineer` gate's mutations are recorded with it. The pull request records the results.

**What the walks cannot see, and a reviewer checks:**
- **A handler outside a `handlers.rs`, or a capture or body read another way.** The guards count one spelling in one file name. A route reads a capture through `PathParam` and a body through `JsonBody` (coding standard §2.6).
- **A request date field of a type the source guard does not look for**, or a request struct outside its reach, is read through a `storable` helper.

## 6. Revisit When

- **A repeated key's overwritten value is found to reach a bind**, or a route must accept a repeated key with meaning. The walk then moves onto the bytes, or the duplicate is refused before the `Value` is built.
- **A caller needs every out-of-range date in a body at once**, such as a bulk import. Option H's per-service check is weighed then for that route.
- **A request date type other than `NaiveDate` or `DateTime<Utc>` reaches a bind**, or chrono's range changes. The helpers and the guard extend, or the bound is restated.
- **A third kind of unstorable value is found**, ADR-0044 §6's trigger, which still stands. It joins `utils::storable` in whichever of the three extractors reads it.
