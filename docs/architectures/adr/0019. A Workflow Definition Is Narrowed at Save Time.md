# ADR-0019 — A Workflow Definition Is Narrowed at Save Time

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-28 (`D-37`, `D-41`); bounded 2026-09-01 (`D-46`) · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** `D-37`, `D-41`, `D-46`, [ADR-0005](0005.%20An%20Internal%20Workflow%20Engine%20Instead%20of%20BPMN.md), [ADR-0016](0016.%20An%20Unenforceable%20Rule%20Refuses%20Rather%20Than%20Passes.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from `D-37`, `D-41` and `D-46` in [Product Backlog](../../../projects/planning/02.%20Product%20Backlog.md) §6.1; the operative statements are [JWSS](../../schema/JSON%20Workflow%20Schema.md) §5.3 and S12 (standard §9).

JWSS declares six `assigneeType` values and Kelir can resolve four. `MANAGER_OF_OWNER` needs a user-to-manager edge — `departments.manager_party_id` names a **party**, and party-to-user is not a resolvable relation in this schema — and `EXPRESSION` needs a directory context that JWSS §6.1's condition context (document, formData, variables, actor) does not carry. A definition using either would publish cleanly and then fail to assign its first task. The same shape appeared for `requiresComment` on an `AUTO` transition: an edge with no caller, demanding a reason it can never be given.

## 2. Decision

**A definition the engine could never run is refused when it is saved, with a message naming what to use instead. A definition the engine can run is not refused, however unusual it looks.** The narrowing is by *resolvability*, not by taste.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. Refuse the unrunnable at save; permit everything runnable** | `D-37`'s two assignee types, `D-41`'s S12; `D-46` on the other side of the line | **Chosen** |
| B. Accept and fail at the transition | Stay literally open to the whole vocabulary | Rejected — the stalled instance nobody is told about that #176 AC1 names |
| C. Resolve `MANAGER_OF_OWNER` through `manager_party_id` anyway | Use the column that is nearly right | Rejected — routes an approval to somebody chosen by a coincidence of data, which is worse than refusing |
| D. Also refuse a non-final state mapping to `DRAFT` | Narrow further, on the same instinct | Rejected (`D-46`) — it would refuse the specification's own example, and the mapping is not wrong |

### A. Refuse the unrunnable — chosen

It is `jfss.rs`'s discipline applied to the other definition kind: *a definition is written once and executed many times, and the execution path has no good failure.* It is a **registry-level narrowing of an open vocabulary** rather than a departure from the specification — exactly as `LookupSource` narrows JFSS's open component `type`. `workflow::domain::graph::AssigneeType` has no variant for either refused value, so an unrepresentable state cannot be forgotten in a `match`. S12 refuses `requiresComment` on an `AUTO` transition in the meta-schema beside S5, because the normative artifact already answers it.

### D. The boundary, and why it is not inconsistent

`D-46` (#278) is the counter-case and defines the line. A state's `mapsToDocumentStatus` may be `DRAFT` — the platform enum carries it, JWSS §10's own worked example maps its initial state that way — so a document can be `DRAFT` while holding a number, a `RUNNING` instance and an open task. That was **not** refused, for three reasons: it would make the implementation refuse the document it implements; the mapping is not wrong, since `DRAFT` means *editable* and a process wanting its subject editable is a modelling choice; and narrowing would not have closed the class anyway, because `RETURNED` also runs with a live process by design. The defect was a downstream guard reading `status = 'DRAFT'` as a proxy for *has no live process* — so the guard was fixed to read `workflow_instances`, which stays true whichever mapping an author picks.

## 4. Consequences

**Positive** — a definition that stores is a definition that can run. The failure moves from a stalled instance at run time to a message at authoring time, addressed to the person who can fix it.

**Negative** — two declared `assigneeType` values are unavailable, and a workflow author reading JWSS finds six where Kelir serves four. **Recorded in the standard, not only in code**: JWSS §5.3 carries the table, because a specification listing six against an implementation serving four is exactly the gap discovered at the worst moment.

**Not settled** — a definition mapping a non-final state to `DRAFT` still publishes with nothing said about it. That is the missing publish-WARNING channel `domain::jwss`'s header already records for S8, and it stays one gap rather than becoming two.

## 5. Compliance

The refusals live in `workflow::domain::jwss` at save; `AssigneeType` has no variant for the refused values, so the compiler holds the narrowing. `a_transition_that_requires_a_reason_refuses_a_decision_without_one` and two tests in `workflow_engine.rs` (one seen red against the guard removed) hold the run-time half. The JWSS meta-schema is compared byte-for-byte with the specification.

## 6. Revisit When

A user-to-manager relation exists (FR-ORG-002's reporting line) — which makes `MANAGER_OF_OWNER` resolvable and moves it back into the vocabulary — or the condition context grows the directory access `EXPRESSION` needs. Either way the narrowing shrinks; it is not re-argued.
