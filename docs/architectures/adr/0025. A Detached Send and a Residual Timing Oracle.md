# ADR-0025 — A Detached Send, and a Residual Timing Oracle

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-27 · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** `D-31`

## 1. Context

**Recorded retrospectively on 2026-09-01** from `D-31` in [Product Backlog](../../../projects/planning/02.%20Product%20Backlog.md) §6.1; the operative statement is the module header on `modules::auth::reset` (standard §9).

The forgot-password endpoint answers the same body whether or not the identifier exists — and was an account-enumeration oracle **by timing**. #202 measured it: `request_reset` awaited a complete SMTP transaction before writing the `202`, so a known account answered in a p50 of 90.1 ms and an unknown identifier in 9.8 ms, ranges not overlapping, on a route deliberately left off the rate limiter. The module header claimed "no branch a caller can time".

## 2. Decision

**The mail send is detached from the request, and the residual gap is documented rather than padded.** `Mailer::send_detached` hands the message to the runtime; re-measured the same way, 26.4 ms against 10.5 ms. **The oracle is narrowed, not closed**, and the header says so with both numbers.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. Detach the send; state the residual** | Costs nothing, removes most of the signal | **Chosen** |
| B. Also detach the token issue | Would flatten both paths to one indexed `SELECT` | Rejected — breaks the resend throttle |
| C. Pad the fast path to a fixed budget | The control that would actually close it | Rejected for now — a different failure mode, and worth taking with a threat model rather than as a finding fix |

### A. Detach — chosen

`send` already reports no failure to anybody, so awaiting it only ever bought the caller a measurement.

### B. Detaching the token issue too

`RESEND_COOLDOWN_SECONDS` is enforced by reading the last issued row before inserting the next, and nothing in the schema stops two of those interleaving — concurrent requests would each see no recent token and each send a link. **Trading a mailbox-flooding control for 16 ms of a timing side channel is the wrong side of that trade.**

### C. Padding

A budget too low is a new oracle; a budget too high is a request-holding denial-of-service surface, on the one route that must stay cheap.

## 4. Consequences

**Positive** — the dominant signal is gone at no cost, and the claim in the module header is now true of what was measured rather than of what was intended.

**Negative, accepted and stated** — an enumeration oracle stays open at **16 ms**, reachable by a caller who can measure a loopback-quality connection to the deployment. Recorded so the next reader finds a decision rather than an oversight.

**Neutral** — the general lesson is in the record: a header asserting a security property is a claim, and a claim nothing measures is how this one survived.

## 5. Compliance

`the_answer_does_not_wait_for_the_mail_to_be_sent` in `tests/auth_password_reset.rs`, held by an injectable slow transport the suite did not have before. The residual is a number in the module header, not an assertion — closing it is option C's job.

## 6. Revisit When

The endpoint gets a threat model, which is when padding is worth taking properly; or the route gains rate limiting, which changes what a measuring caller can do with 16 ms.
