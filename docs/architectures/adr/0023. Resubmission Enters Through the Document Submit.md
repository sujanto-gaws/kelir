# ADR-0023 — Resubmission Enters Through the Document Submit

**Status:** Adopted · **Last updated:** 2026-10-20 (a note on option C: a `RETURNED` state may declare the owner's task, and the resubmit closes it, and §4.1 carries the documents that changed with it, [#667](https://github.com/sujanto-gaws/kelir/issues/667); the creator and the submitter can differ on a first submit, [#700](https://github.com/sujanto-gaws/kelir/issues/700))

**Decision date:** 2026-08-29 · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** `D-42`, [ADR-0005](0005.%20An%20Internal%20Workflow%20Engine%20Instead%20of%20BPMN.md), [ADR-0022](0022.%20Numbering%20Counters%20Live%20in%20Per-Scope%20Buckets.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from `D-42` in [Product Backlog](../../../projects/planning/02.%20Product%20Backlog.md) §6.1; the operative behaviour lives in `document::service::submit` and [JWSS](../../schema/JSON%20Workflow%20Schema.md) §10 (standard §9).

A return sends a document back to its author; a resubmission brings it up again, keeping its number (#183 AC5). But JWSS §10's own example leaves `RETURNED` **stateless** — no `task` — with a `RESUBMIT` edge `allowedBy: "OWNER"`. Every transition Kelir could fire went through `POST /workflow/tasks/{id}/decision`, which is addressed by a task id, and there is no task.

## 2. Decision

**`POST /documents/{id}/submission` fires `RESUBMIT` when the document is `RETURNED` and its process offers that edge.** One endpoint, two shapes behind it.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. The document's own submit fires the edge** | Same button, same act | **Chosen** |
| B. A document-addressed route for the edge | A second endpoint | Rejected — asks the screen to know which of two verbs its submit button means, and the answer is *look at the status*, which the server already does |
| C. Give `RETURNED` a task assigned to the owner | Reuse the existing endpoint | Rejected — it would work and it would be a lie about the queue (see the 2026-10-20 note) |

### A. The submit — chosen

It is the same act: the author corrects the document and sends it.

### C. Manufacturing a task

A task is what puts work in somebody's inbox, and a returned document is with its author, not in an approver's list. Manufacturing one would make the inbox count work nobody is waiting on, and it would contradict JWSS's own example — which the engine is supposed to execute, not correct.

**Note, 2026-10-20** ([#667](https://github.com/sujanto-gaws/kelir/issues/667), `D-113` A). C was about the engine creating a task the definition did not declare, and that stays rejected. **A definition may declare one**: a `RETURNED` state with a `task` for the owner's correction is valid JWSS, and the workflow builder lets an author draw it. Then the queue is not lied to, because the author asked for the work to be counted. The resubmit still enters here, through the document's submit, and it now closes that task before it fires `RESUBMIT`: `COMPLETED` with no `action`, by the resubmitter, with one `workflow_task_history` row whose verb is `RESUBMIT`. Before #667 the task stayed open, so the next state's task was refused with a 409, or the instance kept an open task in a state it had left.

**Also rejected: inferring the target — "send it back one step".** #183 AC2 refuses it and is right: the moment a definition has a branch, *one step back* is ambiguous and each reader resolves it differently. The definition's `to` already names the target, so **no JWSS change was needed** — the property that would have been added already exists.

## 4. Consequences

Three consequences, each taken deliberately:

- **`is_editable` splits from a new `is_discardable`.** A returned document may be corrected and may **not** be deleted: it holds a number, a status history and a live process, and deleting it would strand the instance that returned it.
- **The submit allocates nothing on a resubmission**, under either gap policy — not *allocates and discards*, which would leave a permanent hole per correction round on a gap-tolerant rule ([ADR-0022](0022.%20Numbering%20Counters%20Live%20in%20Per-Scope%20Buckets.md)). `mark_submitted` `COALESCE`s the number, so keeping it is a property of the statement rather than of the caller.
- **The resubmission's `AssignmentContext` carries the document's `created_by`, not the caller.** ~~The two coincide on a first submit and need not here~~ The creator and the submitter can differ on a first submit too, since a submit needs only `document:submit` (corrected 2026-10-20, [#700](https://github.com/sujanto-gaws/kelir/issues/700)), and `allowedBy: "OWNER"` must refuse somebody who merely holds `document:submit`. That also corrected `start_workflow`, which had passed the caller into the owner slot — latent while the creator was always the submitter, visible the moment a second path could reach it.

**Negative, accepted** — the submit path now has two shapes behind one endpoint, and the module header has to say which is which. The alternative was two endpoints and a client that chooses between them, which moves the same branch somewhere it can be got wrong by more people.

## 5. Compliance

`a_returned_document_is_corrected_resubmitted_and_keeps_its_number` in `workflow_engine.rs` is red against the `COALESCE` removed. `is_discardable` is a separate predicate from `is_editable`, so the deletion rule cannot drift back into the editability one.

## 6. Revisit When

A definition needs a resubmission that is *not* the author's submit — a delegate correcting on their behalf, say — which is a new actor question rather than a re-opening of the endpoint's shape.
