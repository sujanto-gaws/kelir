# ADR-0008 — One JSON Logic Engine on Both Sides

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-24 · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** `D-10`, `D-15` (open), [ADR-0006](0006.%20Metadata-Driven%20Forms%20and%20Lists.md), [ADR-0018](0018.%20Division%20by%20Zero%20Is%20an%20Evaluation%20Error.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from `D-10` in [Product Backlog](../../../projects/planning/02.%20Product%20Backlog.md) §6.1, which holds the full reasoning and remains the operative record (standard §9).

A JFSS form carries `calculate` and `conditional` expressions in JSON Logic. The browser evaluates them as somebody types; the server re-evaluates them at submit and overwrites what the client sent (JFSS S8.1, S10.2). **Two runtimes evaluating one expression is the whole risk**: where they disagree, a schema means two different things, and the disagreement surfaces as a persisted wrong number rather than as an error.

The [operator-parity spike](../../../projects/spikes/01.%20JFSS%20Operator%20Parity.md) (#31) found the Calculation Rule Registry naming `json-logic-rs`, which is not a crates.io package. The crate it meant, `jsonlogic-rs` 0.5.0, **returns unknown operators instead of rejecting them** — inverting the Tamper-Proof Pattern: the registry's own §6.1 invoice pattern persisted a grand total of `0` in place of `42`, with nothing logged and nothing returning 400. It also had no custom-operator API, so `sum` — which the registry requires in all three environments — could not be registered at all. This was Phase 4's entry criterion.

## 2. Decision

**Kelir uses `datalogic-rs` 5.2.0 on the backend and its official WebAssembly build in the browser**, in place of `json-logic-js`. Both packages are pinned to the same exact version, and a bump is a parity-affecting change that re-runs the corpus.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. `datalogic-rs` on both sides, same version** | One implementation, compiled twice | **Chosen** |
| B. `json-logic-js` in the browser, `datalogic-rs` on the server | Keeps the 4.1 KB client library | Rejected — strictly weaker: parity becomes a property tests chase rather than one that holds |
| C. Keep `jsonlogic-rs` 0.5.0 | The crate the registry appeared to name | Rejected — unknown operators evaluate to nothing instead of failing; no custom-operator API for `sum` |

### A. One engine — chosen

The spike measured 51 expressions across four evaluators; the two adopted sides agree on **51/51 including the error cases**, so Polyglot Parity holds *by construction* rather than by a test suite chasing it.

### B. Two implementations

The spike calls it strictly weaker: it leaves the five known divergences in place and needs a wrapper per divergence. Measured against `json-logic-js`, the engine agrees on 46/51 after the mandated wrapper — which is why the [`parity/`](../../../parity/README.md) gate holds Kelir's *two own sides* to each other.

### C. The originally named crate

Rejected by the failure that raised the spike: a silent `0` where `42` was expected is the exact inversion of the pattern the product depends on.

## 4. Consequences

**Positive** — one implementation of the semantics, so a form means the same thing in both places without a compatibility layer. The corpus (now 60 cases, from 51) is a CI parity gate.

**Negative — accepted deliberately:** 588 KB gzipped against 4.1 KB for `json-logic-js`, and a licence move from MIT to Apache-2.0. The weight is lazy-loaded — only form pages need an evaluator — and confirmed off the first-load path: the engine builds into its own chunk and a separate `.wasm` asset, with the entry chunk byte-for-byte identical with and without an importer. NFR-PERF-001 baselines view latency rather than bundle weight, so nothing is formally breached; the size is a choice, not a side effect.

**Neutral** — adoption moved to Sprint 7 rather than Sprint 14, because JFSS S8.1 makes a working evaluator a Sprint 8 dependency. What stayed in Sprints 14–16 is the surrounding engine: rule catalogue, dependency graph, cycle detection, error mapping.

**Not settled by this** — the `conditional.logic` tier that no registry governs, and the `regex` params constraint no Rust backend can honour as specified. Both are carried as `D-15`, open.

## 5. Compliance

The `parity/` corpus runs in CI over both sides; a divergence fails the build. Both packages are version-pinned, and a bump is treated as a parity-affecting change.

## 6. Revisit When

The engine stops being maintained, its WebAssembly build stops tracking the crate, or a version bump makes the two sides disagree on a corpus case that cannot be settled by configuration.
