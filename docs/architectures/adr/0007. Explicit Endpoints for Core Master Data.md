# ADR-0007 — Explicit Endpoints for Core Master Data

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-04 (founding) · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** [ADR-0004](0004.%20A%20Modular%20Monolith%20with%20a%20Flat%20Module%20Layout.md), [ADR-0006](0006.%20Metadata-Driven%20Forms%20and%20Lists.md), [ADR-0013](0013.%20A%20Business%20Code%20Is%20Never%20Released.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from the inline `**Decision:**` in [architectures/01](../01.%20Basic%20Framework%20Concept%20and%20Architecture.md) on master-data endpoints, matching [architectures/02](../02.%20Kelir%20Framework.md) §3.9. Those remain the operative statements (standard §9).

Kelir is a metadata-driven framework ([ADR-0006](0006.%20Metadata-Driven%20Forms%20and%20Lists.md)), so the tempting shape for master data is one generic endpoint — `/master-data/{entity}` — driven by the same configuration machinery as everything else. Against that: six entities (suppliers, customers, employees, facilities, products, services) are referenced by the platform itself, and a document's link to a party is not a tenant-configurable relationship.

## 2. Decision

**The six core master-data entities are served by explicit typed endpoints; the generic pattern remains available for configurable RAD entities.** Master data is a hybrid on purpose: platform-defined entities are typed, tenant-defined ones are configured.

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. Explicit typed endpoints for the six, generic for the rest** | The recorded hybrid | **Chosen** |
| B. Generic endpoints for everything | One code path, fully metadata-driven | Rejected — "explicit typed endpoints are safer for long-term systems" (architectures/01) |

### A. The hybrid — chosen

The six entities have platform meaning: a document references a party, an approval routes by department, a facility scopes a permission. Typed endpoints give each of those a schema the API contract can state and a compile-time-verified query behind it ([ADR-0002](0002.%20SQLx%20with%20Compile-Time%20Verified%20Queries.md)).

### B. Generic for everything

Useful for a RAD framework and rejected for the core: architectures/01 records that explicit typed endpoints are safer for long-term systems. The generic pattern is not discarded — it is where configurable entities go.

## 4. Consequences

**Positive** — the six entities have real request and response types, OpenAPI documentation a client can generate from, and per-entity permissions (`master-data:party:read` and siblings) rather than one permission over a generic route.

**Negative** — six surfaces to maintain, and a change to the shared shape touches each. The party aggregate ([architectures/05](../05.%20Core%20-%20Master%20Data%20-%20Party.md)) carries the weight of being both typed and JSON-Schema-described.

**Neutral** — the boundary between "platform entity" and "configurable entity" is now a real line in the product, and new master data has to be placed on one side of it.

## 5. Compliance

The OpenAPI document generated from the handlers is the check: a core entity served generically would have no typed schema in it. Per-entity permission checks are held by the master-data integration tests.

## 6. Revisit When

A seventh entity arrives that is neither clearly platform-defined nor clearly tenant-configurable — the case that would show the line is in the wrong place.
