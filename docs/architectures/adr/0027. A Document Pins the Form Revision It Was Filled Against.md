# ADR-0027 — A Document Pins the Form Revision It Was Filled Against

**Status:** Adopted · **Last updated:** 2026-09-01

**Decision date:** 2026-08-27 · **Deciders:** Product owner · **Supersedes:** — · **Superseded by:** — · **Related:** `D-30`, [ADR-0006](0006.%20Metadata-Driven%20Forms%20and%20Lists.md)

## 1. Context

**Recorded retrospectively on 2026-09-01** from `D-30` in [Product Backlog](../../../projects/planning/02.%20Product%20Backlog.md) §6.1; the operative statement is [Database Schema](../../design/02.%20Database%20Schema.md) §6.2 and §6.6 (standard §9).

Forms are revised by publishing the next revision ([ADR-0006](0006.%20Metadata-Driven%20Forms%20and%20Lists.md)), and a document type points at one. #157 built the document-type update path without deciding what happens when an administrator re-points a type at a different form while a thousand documents of that type already exist — `formId` was a field like any other, and changing it was one PUT. #165 AC3 refused to let that default: *a document rendered against a form it was not filled against is a data-integrity problem that looks like a UI bug*.

## 2. Decision

**Re-pointing is allowed, and existing documents keep the revision they pinned. It is refused only while a document exists that pinned none.**

## 3. Options Considered

| Option | Summary | Verdict |
|---|---|---|
| **A. Allow, on the pinned column; refuse only for unpinned documents** | The guarantee holds by construction where the column is set | **Chosen** |
| B. Refuse re-pointing outright once documents exist | The safe-looking rule | Rejected — a type would be stuck on revision 1 from its first document; that does not protect the revision mechanism, it deletes it |
| C. `NOT NULL` on `documents.form_id` | The structural fix | Rejected — wrong scope: it would forbid a document of a type that binds no form, which §6.2 permits, and would settle a column #167 had not written to yet |
| D. Version the binding | Keep a history of which form a type pointed at, resolve by date | Rejected — that is FR-RAD-012 metadata versioning, unscheduled, and it reconstructs by inference what a pinned column already states |

### A. Pin, and refuse the gap — chosen

§6.6 pins a document's own `form_id` at creation, so a document that pinned one is unreachable from the type's binding and the guarantee holds for it by construction. But that column is **nullable**, and a document that pinned nothing has only its type's *current* binding to render against. Those documents, and only those, are what a re-pointing can damage — so those are what it is refused over. **That is the difference between a guarantee and a comment describing one.**

### C. The structural fix

A migration reaching forward into an unbuilt surface is a constraint whoever builds that surface has to argue with rather than design against.

## 4. Consequences

**Positive** — an administrator can point a type at a new revision so that *new* documents use it, which is the operation the revision mechanism exists for, without touching what old documents render as.

**Negative, accepted** — #167 must pin `form_id` when it creates a document, or every type its documents belong to becomes un-rebindable. That obligation is not left as a note: inserting into `documents` takes a `FOR KEY SHARE` on the `document_types` row, and the re-pointing's `FOR UPDATE` conflicts with it, so the check and a concurrent creation serialize **by the foreign key** rather than by anything a later sprint remembers.

**Neutral** — form revisions remain the only versioning story; FR-RAD-012 is unscheduled and this decision does not anticipate it.

## 5. Compliance

`a_document_created_during_the_rebinding_is_not_missed` in `tests/document_types.rs` holds the lock interaction and goes green when the lock is weakened one step — so the serialization is tested rather than assumed.

## 6. Revisit When

FR-RAD-012 (metadata versioning) is scheduled, which is when option D stops being a reconstruction and becomes a designed history; or `documents.form_id` becomes non-nullable in its own right, which would remove the refusal case entirely.
