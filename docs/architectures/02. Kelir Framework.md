# Kelir Framework  
## Main Backend and Frontend Module Breakdown

**Status:** Adopted · **Last updated:** 2026-08-12

Below is the module breakdown for the **Kelir** framework, based on the previous document-based business application and rapid application development concept.

Where the module lists in this document differ from document 01, this document supersedes it. Document 03 decomposes this document's `IntegrationModule` into the detailed integration-layer modules.

Kelir will be structured as:

```text
Kelir
├── Backend  : Rust modular monolith
├── Frontend : Vue + Vite + TypeScript + Axios + shadcn-vue + Tailwind CSS v4
└── Database : PostgreSQL, with optional MariaDB compatibility
```

---

# 1. Kelir Module Overview

The framework is divided into major module groups:

```text
1. Core / Foundation Modules
2. Security and Identity Modules
3. Master Data Modules
4. Rapid Application Development Modules
5. Document Management Modules
6. Workflow Engine Modules
7. Collaboration Modules
8. Audit and Monitoring Modules
9. Integration and Infrastructure Modules
10. Frontend Application Modules
```

### Authorization Model

Start with:

```text

Role-Based Access Control
```

Later extend to:

```text
ABAC
Attribute-Based Access Control
```

Permission format:

```text
module:resource:action
```

The `resource` segment may be omitted when a module manages a single resource, giving the shorter form `module:action` (e.g. `document:create`).

Examples:

```text

```

`documents.status` is a fixed platform-level enum consisting of the values above. Workflow definitions have their own named states (e.g. `MANAGER_APPROVAL`, `FINANCE_APPROVAL`) which map onto these platform statuses via the workflow definition, so the document lifecycle stays uniform across all document types regardless of workflow shape.

The lifecycle stages these statuses belong to, and the `before_*` / `after_*` hooks each stage exposes, are defined in document 01 §12.
