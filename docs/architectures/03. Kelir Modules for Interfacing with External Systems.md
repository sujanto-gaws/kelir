# Kelir Modules for Interfacing with External Systems

**Status:** Adopted · **Last updated:** 2026-08-12

For **Kelir**, external system integration should not be placed directly inside business modules such as Document, Workflow, or Master Data.

Instead, Kelir should provide a dedicated **Integration Layer** that handles communication with external systems in a controlled, secure, observable, and retryable way.

The modules in this document are the detailed decomposition of document 02's `IntegrationModule` and live under the monolith's `integration/` module directory. Where names resemble document 02 core modules (EventBusModule vs EventModule, IntegrationSchedulerModule vs SchedulerModule, NotificationChannelModule vs NotificationModule, IntegrationAuditModule vs AuditModule), the integration-layer modules handle the external-facing concerns and delegate to the corresponding core modules.

The integration layer should support:

```text
ERP
CRM
HRIS
Finance systems
E-signature providers
Email/SMS providers
Identity providers / SSO
Payment systems
Tax or government systems
Banking systems
File/SFTP servers
BI tools
Message queues
Webhook consumers
External REST APIs
```

# 1. High-Level Integration Architecture

```text
External Systems
        ↑
        ↓
+--------------------------------------------------+
|              Kelir Integration Layer          |
|                                                  |
|  API Gateway / Inbound API                       |
|  Webhook Receiver                                |
|  Connector / Adapter                             |
|  Outbound API Client                             |
|  Data Mapping / Transformation                   |
|  Event Bus / Outbox                              |
|  Scheduler / Sync Job                            |
|  File Exchange                                   |
|  Credential / Secret Management                  |
|  Integration Log / Monitoring                    |
|  Retry / Dead Letter Queue                       |
+--------------------------------------------------+
        ↑
        ↓
Kelir Core Modules
  - Document Module
  - Workflow Module
  - Master Data Module
  - Notification Module
  - Audit Module
```

# 5. Integration Patterns Supported by Kelir

Kelir should support several integration patterns.

---

## 5.1 Synchronous API Integration

```text
Kelir calls external API directly and waits for response.
```

Example:

```text
Kelir creates Purchase Order in ERP.
ERP returns success/failure immediately.
```

Use when:

- Response is needed immediately
- Process must wait for external result
- Data volume is small

---

## 5.2 Asynchronous Event Integration

```text
Kelir publishes event.
Worker or external system processes it later.
```

Example:

```text
DocumentCompleted event published.
ERP worker consumes event.
ERP creates Purchase Order.
```

Use when:

- Immediate response is not required
- System needs better resilience
- Process can be retried

---

## 5.3 Webhook Integration

```text
External system calls Kelir when something happens.
```

Example:

```text
E-signature provider sends webhook when contract is signed.
Kelir updates document status.
```

Use when:

- External system can notify Kelir in real time
- Callback-based status update is needed

---

## 5.4 Scheduled Batch Integration

```text
Kelir runs scheduled job to sync data.
```

Example:

```text
Every 1:00 AM, Kelir syncs employees from HRIS.
```

Use when:

- External system has no real-time API
- Data can be synchronized periodically
- Bulk data processing is needed

---

## 5.5 File-Based Integration

```text
Data is exchanged through files.
```

Example:

```text
Bank sends payment report as CSV via SFTP.
Kelir imports the file and updates payment status.
```

Use when:

- External system only supports file export
- Batch processing is acceptable
- Regulatory or banking channel requires file exchange

---

## 5.6 Message Queue Integration

```text
Systems exchange messages through queue or topic.
```

Example:

```text
ERP publishes InvoicePosted message to Kafka.
Kelir consumes it and updates invoice document.
```

Use when:

- High volume
- Asynchronous processing
- Multiple consumers
- Event-driven architecture is needed

# 9. Important Integration Rules

## Rule 1

Do not call external systems directly from Workflow or Document business logic.

Use:

```text
Workflow → Integration Service → External System
```

---

## Rule 2

Do not store sensitive secrets in plain text.

Use:

```text
Environment variables
Secret manager
Encrypted credential store
```

---

## Rule 3

Always log integration activity, but mask sensitive data.

Mask:

```text
password
token
secret
bank account
credit card
personal sensitive data
```

---

## Rule 4

Use correlation ID across logs.

Example:

```text
Document ID
Process Instance ID
Integration Log ID
External Request ID
```

---

## Rule 5

Make integration idempotent where possible.

Example:

```text
If Purchase Order already created for document PR-2026-000123,
do not create duplicate Purchase Order.
```

---

## Rule 6

Support manual retry for failed integration.

Operational users should be able to:

```text
View failed integration
Inspect error
Fix mapping or data
Retry integration
```
